## 1. 方針転換（2026-07-12 ユーザー合意）

**較正対象を「回数制限のない反復可能ボスバトル」へ転換し、統計的較正を導入する。**
- 背景: B案（turn-by-turn）は「会心の分離測定が実機で不可能＝単一サンプル・会心RNGに脆い」ことへの守りだった。
  反復可能ボスは this を覆す＝**N試行の集計で会心RNGを平均化・非会心アンカーを反復で捕捉・会心/急所率を頻度で実測**できる。
- ボスバトル条件（ユーザー確認済み）: (a) 全属性で複数ボス存在＝選択可能 (b) HPは小〜膨大まで自由＝ホライズン長を確保可能
  (c) **多くがエンドコンテンツで「有利属性以外からの攻撃耐性」持ち・未定量・有志検証ほぼなし**。
- **(c)への回答（合意済みの構造）**: 未定量耐性は**最終ダメージに乗る単一の大域スカラ**（affinity/defと同種）＝
  **形状較正（会心率・baseline・成長・cap×会心順序・成分比）は比/形状ベースのため耐性に非依存**で成立する。
  絶対レベルの1スカラだけが耐性に依存 → **光有利（闇属性）ボス1体をアンカー**にすれば既知の有利倍率でレベルが確定。
  モデル確定後は逆に**各ボスの未定量耐性を実測残差として定量化できる**（副産物・エンドメタ価値）。
  ※モデルとボス耐性を**同時にfitしない**（識別不能）: 形状→有利ボスでレベル→残差で耐性、の順に解く。

## 3. 測定プロトコル（統計的較正・第1走）

### 3.1 装備2config × 固定押し順 × N試行
- **config A（full-crit・現行装備）**: 会心急所ほぼ100%＝**決定的**（hit毎の値が一定・RNGなし）。成長カーブ・成分比・絶対レベルを少数走でクリーンに取得。
- **config B（crit-off・会心発動率スキルのみ外す）**: 中程度の会心率（30〜60%目安）にし、**同一走・同一slotで会心/非会心のマッチペア**を取る
  ＝C25の決定打（capの内側/外側判別: ペア比が素の×1.5なら外側・cap圧縮なら内側）。**武器本体は残し最小限のダウングレード**。
- 試行数: まず**config Bを中心にN=20〜30走**（会心率実測と非会心アンカーの分布用）。config Aは3〜5走（決定性確認）。
- 急所の隔離は**中立ボスで自動オフ**（急所=有利属性のみ発動・実機確認済み）＝装備を触らず切れる。第2走以降:
  | | config A（会心あり） | config B（会心低） |
  |---|---|---|
  | 有利ボス（急所ON） | 成長/成分比/絶対レベル | 非会心＋急所ペア |
  | 中立ボス（急所OFF） | 会心のみ隔離 | **非会心非急所＝純rawアンカー** |

### 3.2 記録項目（trialXX.md・旧sim03プロトコルを吸収）
- 押下毎: キャラ/成分（通常/バースト本体/追撃/ロボ追撃/エジソン英霊武器追撃/judg/streak）・値・**会心/急所マークの有無**。
- 各ターンのメインフェイズ開始/終了時: **契晶ストック/累計/連理魔力**（回帰アンカー・sim02全10点一致の維持確認）・**バーストゲージ5人分**。
- **C24実機確認2点**: 補助ロボ（黄アビ反応）のゲージ増分実測／エレイン1のゲージ効果仕様（対象・英霊100条件）。
- **C23追検証**: 各ターン最初のjudgのフェーズ（アビ=ph0/バースト=ph1/通常=ph2）＝通算連続モデルの追認。
- 各ターン末ボスHP%・敵行動・反撃・DOT。
- バフ実stack数（アサルト系/旺盛/光属性UP/legend閾値/特殊/防御DOWN）＝成長不足の枠局在（B1継承）。

### 3.3 分析計画（データ受領後）
1. `analysis/quantitative_analysis.md`: config忠実度（replay=キャッシュ一致・dispAtk同梱で完全再構成可）→ 試行間集計
   （会心/急所率の実測・非会心アンカー抽出・成分別平均/分散）→ C25 raw枠帰属・cap×会心順序の判別・C5追撃cap再較正（C3統合）。
2. `analysis/qualitative_analysis.md`: 実機所感・観測メモの整理。
3. `analysis/integrated_analysis.md`: 統合→モデル修正→golden再fit→ def/耐性スカラの確定 → kill-turnゲート再判定（延期中）。

## 4. 承認待ちの改善提案（Claude Code・次セッションで判断）

- **P1**: `data/config.json` は**探索キャッシュexportをそのまま兼用**（dispAtk同梱済み＝手書き重複を避ける）。不足メタ（敵HP開始状態・装備config名）は各 trialXX.md 冒頭のメタヘッダで補完。
- **P2**: trialXX.md は**1試行=1ファイル・連番**（統計的較正のN試行対応）。装備configが複数ある場合はヘッダの「装備config名」で紐付け（config JSONも configA.json/configB.json と分ける）。
- **P3**: quantitative は「手法・スクリプト参照・入力データ」の明記を必須化（再現性担保）。
- **P4**: 会心率を落とす具体手段（どのスキル/武器を外すか）は装備実物依存のため、config B 確定時にユーザーと具体指定を協議。
