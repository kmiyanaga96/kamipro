## ユーザー所感（2026-07-22・移行設計の一次メモ）

> 実機プレイ感。押し順ヒューリスティック（cands.s）とアビ回数モデルの設計指針。**game内アビ番号(1/2/3/4)とコードのキー(roy/pike/consort/factor)の厳密対応は移行時に要確認**（下記は現実装からの推定対応つき）。

### 1. ナポレオン（押し順の勘所）
- **2アビ＝「強化数(バフ数)10以上か否か」だけが判定ゲート** → **10以上になったら最速で打つ**と機会損失が少ない。→ sim: 該当アビの `cands.s` を「buffCount≥10で高スコア（早撃ち）」に。
- **1アビ・3アビ＝なるべく最後に打ちたい** → sim: 低スコア/終盤寄せ。
- **4アビ＝ifishant同系統のアビ短縮効果** → 現実装 `factor`（ディシジフ・labelSuffix`(全CD-1)`）が「バフ10以上で全体アビCD-1・BG+30」＝これが該当濃厚。他アビの使用回数を伸ばすレバー。
- 現実装の関連ゲート（要突合）: `consort`（アーティオリ）=(2+0.5×バフ数)倍・**バフ20以上で2回**・上限250万。`pike`=バフ15以上で急所/会心追加。`roy`=バフtierで全攻撃ダメプラス。→ **「バフ数」が全アビの主軸**なのでbuffCount正確性が押し順の要。

### 2. アリアンロッド（回数制限×短縮の相互作用）
- アリアンのアビには**回数制限**があるが、**自身の短縮効果／ifishant／ナポレオン4アビ(factor)** などのCD短縮で**上限超過発動**が可能になる。
- **扱い＝エレインのアビが ifishant でリキャストできる事象に近い**（現実装の `ifAlone/ifLegend/ifKnights/ifPactcore` パターン）。→ sim: アリアンの各アビ（`holy` T.holy<2 / `elegant`+`elegant_re` の回数ゲート等）に、**短縮ソース由来の条件付き+1枠**を同型で付与する設計。現 `elegant_re` guard `T.elegant<(t===1?4:3) && g>=40` を、この上限超過ルートと突合。

### 3. アリアンロッドのHP参照（実装依存）
- アリアンには**HP参照項目**があるため、**厳密にHPと連携させたシムはHP実装以降**（＝未確定Phase i「味方生存/現在HPモデル」後）。それまでは近似 or 該当項目を保留。現エンジンは旺盛を**最大HP前提に簡略化**済み（現在HP参照スキルは未モデル）＝アリアンHP項も同じ制約下。
