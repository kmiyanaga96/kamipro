## 1. なぜ「構造修正が先」か（実施順序の絶対原則）

`gamedata/md/その他/damage_frames.md` とエンジンの突合（2026-07-16）で**式の構造そのものの修正**が確定的になった（C31〜C35）。構造修正は pre-cap raw を変えるため、**先にスカラをfitすると構造誤差をスカラが吸収し、修正後に全fitがやり直しになる**。順序は「構造修正 → スカラfit」固定。

| 修正 | 内容 | 方向 | 接続 |
|---|---|---|---|
| C31 | アビダメUPを倍率へ**加算**: `naForAbi×mult×(1+abiUP)` → `naForAbi×(mult+abiUP合計)`（judg/effond/consort/droid反応/`_spendGaugeAbi` 系すべて。droid_buf の db.dmg も同枠加算へ） | シム過大の是正 | **C30（judg ph0 ×0.76〜0.78 シム過大）の真因候補**・pre-cap ×1.84過大 |

## 4. 単独データ取得メニュー（M走・実機・ユーザー作業）

共通ルール: 各測定 **2〜3走**（C28 ロールRNG median3.5%/p90 12.4% の吸収）／**会心（大数字演出）・急所マークを全hit記録**（fitの主アンカーは**非会心・非急所hit**）／**hit数を記録**（C29連撃: 通常攻撃アンカーは1hit標本のみ採用）／**表示はceil規約**／**HP%併記**（旺盛はHP50%以下で消失）／記録は `data/record_skeleton.md` を複製した `data/trialNN.md`（メタヘッダの「測定メニュー」に M1/M2a/M2b/M3/M4 を記入）。

### M1. 無アビ素走（最優先・C25 baseline分離の決定打）
- **目的**: バフゼロアンカー＝「baseline不足」と「ターン跨ぎ成長不足」を回帰でなく**直接観測で**分離。
- **手順**: アビを一切押さずターン終了のみで2〜3T。T1攻撃フェイズ=全員初期ゲージ100でフルバースト（バフ無しバースト本体×5＋追加ダメ＋ストリーク）。T2以降=ゲージ<100キャラの**素の通常攻撃**（hit数つき）。
- **fitでの使い方**: バフ項0＝残る係数は configB ギア（既知）と baseline のみ。非会心非急所hitなら未知数は実質 baseline スカラ1個。
- **注意**: 敵フェイズ被弾でHP減（旺盛変動→HP%記録）。2走目以降は撤退→再入場でリセット。ヘカテー反撃が出たら値を記録し押下計に混ぜない。

### M2. judg 単独（C31 加算/乗算の判別＋C30 per-hit cap）

**知りたいこと（2つ）**
- **C31**: judg の abiダメUP が「倍率へ**加算**（3+abi_dmg）」か「**乗算**（3×(1+abi_dmg)）」か。
- **C30**: judg ph0 の per-hit cap＝10hitが頭打ちになる高さと、ターンを跨いだ緩やかな増加（実機5.8M→7.1M）の形。

**⚠この装備での判別方針（先に理解する）**: configB は `abi_dmg=2.52` が大きく、judg は減衰の深部に入る（1hitのraw≒270〜530万 vs abiのcap起点≒70万・減衰slope0.04）。このため **10hitはほぼフラット（cap飽和）** になる見込みで、**加算か乗算かは「その場の数値差」では判定できない**（post-cap後は両者の差が1割強まで潰れる）。
→ **現場でやることは"良い絶対値と成長データを揃えるだけ"**。判別は後日のfitで、**M1で得た naForAbi ＋ M2aのph0絶対値 ＋ ph0の成長形状**を同時に合わせて行う。**その場で加算/乗算を見分けようとしなくてよい。**

#### M2a 手順（1セット＝撤退をはさむ2本の走）

- **走A（droidなし・N=0基準）**
  1. 戦闘開始直後、**最初の押下を judg にする**（他アビは一切押さない）。
  2. **ph0の10hitを1発ずつ全記録**（値・会心・急所を各hit）。
  3. そのまま**撤退**。
  - メモ: 開始時なので omni・ムーンコードが有効 → **有効バフを§0に明記**（fitで基準を合わせるため）。開始直後のjudgは**必ずph0**（C23）。

- **走B（droidあり・N>0）**
  1. droid を設置し、反応を起こしてから judg を押す。
  2. **judg押下時点の droid_buf スタック数 N を明記**（増分は abiダメ+3%×N・cap+2%×N）。
  3. ph0の10hitを全記録 → **撤退**。
  - できれば **N=1 と N=2〜3 の2水準**（水準ごとに走を分ける）。
  - droid反応を起こす赤アビは**余計なバフの少ないもの**を選ぶ（混ざったら§0に記録）。

- **共通（両走）**
  - **各条件2〜3走**（C28ロールRNG吸収）。
  - **10hitがフラット（同値頭打ち）か階調ありかを必ず記録** ← cap飽和の即時シグナル（C30直証）。フラットなら「その値＝そのNでのcap高さ」。
  - 2押し目以降にjudgフェーズ（ph1/ph2）が出たら、それも記録。

#### M2b（judg・装備替え）→ **本simではスキップ確定（2026-07-20）**
- abi_dmg を**単独で載せている装備/トグルが編成に存在しない**（六欲天デレクターレ＝複合スキル武器でエラボレイト単独除去不可・武器ごと外すと多重交絡）ため、abi_dmg 2水準の大レバーが作れない。**M2bは実施しない**。C31判別は上記「同時fit方式」で行う。
- （fit後もC31が曖昧な場合の**最終手段としてのみ**保留）六欲天デレクターレを丸ごと外し全スキルを記録して他スキル分を解析的に差し戻す案。通常は使わない。

### M3. 旺盛スタック（C32 の100%超え実在確認）

**知りたいこと**: judgでなく通常攻撃側で、旺盛が **一律100%cap**（現行sim）か **2段cap**（C32仮説＝ウェポン100%＋アビバフ合計200%）か。**ムーンコード（ヘカテー2アシ・vigor+0.3552）**をアビバフ側の旺盛レバーに使う。

**⚠測定原理（ヘカテー通常の T2 vs T3 比＝旺盛だけが動く）**: ムーンコードは vigor と会心率+50% のみ・**モデル上ヘカテー専用**（`_naOwner===effond所有者`）。会心は実効≒100%（全hit会心）だが、**会心倍率は会心hit同士で相殺**（ムーンコードは会心"率"を上げるだけ）＝比には効かない。急所も**同一急所状態でマッチ比較すれば相殺**。→ **非急所↔非急所・急所↔急所の各層でT2/T3比**を取れば、残るは旺盛だけ。

#### M3 手順（1セット＝撤退不要・T1-T3を通しで）
1. **T1: アビ・バーストを一切押さない（捨てターン）**。通常攻撃は出てよい（測定しない）。狙い＝omni（dur1）を失効させ、ムーンコードを1T消費。
2. **T2: 通常攻撃（アビ/バースト無し）**。この時 **ムーンコードON・omni失効済**。→ **5人全員の通常hitを会心/急所つきで全記録**。
3. **T3: 通常攻撃（アビ/バースト無し）**。**ムーンコードOFF**（開始時2T・再発動なし＝アビ0のため）。→ 同様に**5人全員の通常hitを全記録**。
- **各セット2〜3走**（C28ロールRNG）。**HP100%を両ターン維持**（旺盛はHP依存＝HP50%以下で消失。各ターンHP%記録）。

#### 判別（configB Gv=0.6876・vigor_mooncode=0.3552）
ヘカテー通常の **T2/T3 比**（同一急所層でマッチ）:
- **一律100%cap（現行sim）**: (1+min(0.6876+0.3552,**1.0**))/(1+0.6876) = 2.0/1.6876 = **1.185（+18.5%）**
- **2段cap（C32仮説）**: (1+min(0.6876+0.3552,**2.0**))/(1+0.6876) = 2.0428/1.6876 = **1.210（+21.0%）**
- 差は**比で約2.1%**（ヘカテー非急所≒590kなら T2 が 699k[一律] vs 714k[2段]＝差約15k）。**非急所hitを複数×2〜3セットで median**して解像する。急所層でも同比が出るはず（クロス検証）。

#### 内蔵の対照実験（タダ）
- **edison/yamato/tetra/elaine の通常も両ターン記録**。ムーンコードはヘカテー専用のはず＝この4人は **T2≈T3（変化なし）** が期待。
  - もし4人も T2→T3 で下がるなら **ムーンコードは実は全体対象**（モデル要修正の発見）。どちらでも収穫＝**mooncodeスコープの検証**を兼ねる。

#### ボスは cath_palug 続投（変更不要）
- T2/T3は**比**なので affinity/隠れ耐性は相殺＝中立ボスに替えても精度は上がらない。急所は**マッチ比較で相殺**でき非急所を"消す"必要なし（~65/35で両層とも十分取れる）。中立ボス化は環境跨ぎ（§2禁止）・アンカー性喪失の損。
- （任意・別枠）中立ボスで急所マークが消えるか観察すれば **C35〔急所の有利属性ゲート〕の直接検証**になる。C32判別には不要。

## フォルダ構成・分析ワークフロー（テンプレ標準・sim03以降の新構造）

| パス | 内容 | 責務の境界 |
|---|---|---|
| `data/config.json` | **基本情報JSON（=configB）**＝編成・押し順・敵・GEAR・per-char表示ATK等を全記録 | 一次情報。手を加えない |
| `data/configB_gear_panel.md` | 装備パネル転記＋GEAR整合検証（§2-2） | 一次情報 |
| `data/record_skeleton.md` | **記録スケルトン（コピー原本）**。複製して `trialNN.md` を作る | 様式定義。sim内全trialで統一 |
| `data/trialNN.md` | **実機データ原本**（複製・加工せず。**複製とpushはユーザーが行う**） | 一次情報 |
| `analysis/per_trial/trialNN_{quant,quali}.md` | 単trial中間集計（trialNN.md 1本のみ入力） | trial横断は書かない→rollup |
| `analysis/{quantitative,qualitative}_analysis.md` | trial横断rollup（per_trial全trial入力） | 生trialを再オープンしない |
| `analysis/integrated_analysis.md` | 統合（両rollupのみ入力）＝Cx遷移・モデル修正判断・golden影響・次アクション | 新規集計を持ち込まない |

> 分析は `trial → per_trial → rollup → integrated` の map-reduce（コンテキスト有界化）。命名は `trialNN.md`／`trialNN_quant.md`・`trialNN_quali.md`（NN 2桁で1:1）。
> sim04 特記: trial は測定メニュー横断で通し番号（例 trial01=M1走1・trial02=M1走2・trial03=M2a走1…）。メニューIDはメタヘッダで判別し、rollup はメニュー別に層別集計する。
