## 1. なぜ「構造修正が先」か（実施順序の絶対原則）

`gamedata/damage_frames.txt` とエンジンの突合（2026-07-16）で**式の構造そのものの修正**が確定的になった（C31〜C35）。構造修正は pre-cap raw を変えるため、**先にスカラをfitすると構造誤差をスカラが吸収し、修正後に全fitがやり直しになる**。順序は「構造修正 → スカラfit」固定。

| 修正 | 内容 | 方向 | 接続 |
|---|---|---|---|
| C31 | アビダメUPを倍率へ**加算**: `naForAbi×mult×(1+abiUP)` → `naForAbi×(mult+abiUP合計)`（judg/effond/consort/droid反応/`_spendGaugeAbi` 系すべて。droid_buf の db.dmg も同枠加算へ） | シム過大の是正 | **C30（judg ph0 ×0.76〜0.78 シム過大）の真因候補**・pre-cap ×1.84過大 |
| C32 | 旺盛を2段capへ: `min(ウェポン分,1.0)+アビバフ分 → min(合計,2.0)`（現行=一律100%クランプ。GEAR.vigor=ウェポン分／absolute・legend・mooncode等=アビバフ分と分離管理） | シム過小の是正 | **C25（全体×1.430 シム過小）の寄与候補** |
| C33 | applyGear に technica→na_dmg エイリアス（現行=`box:'technica'` が GEAR_BOXES 不在で黙殺） | UI自動計算経路の欠落是正 | パネル手入力運用では実害なし・+300%capはtodoコメント可 |
| C34 | バーストダメUP合計に+500%上限: `coef_a + min(バフ+ウェポン合計,5.0) + selfBonus`（大幅UP=selfBonus は上限外のまま） | シム過大方向 | C25 の枠帰属に必須（＝baseline不足の露呈） |
| C35 | 軽微3点: (a)恐傷を与ダメUP枠へ同枠加算 (b)final_dmg を減衰後適用へ (c)急所に有利属性ゲート | — | 現編成・現ボスで実害0だが式整合 |

## 4. 単独データ取得メニュー（M走・実機・ユーザー作業）

共通ルール: 各測定 **2〜3走**（C28 ロールRNG median3.5%/p90 12.4% の吸収）／**会心（大数字演出）・急所マークを全hit記録**（fitの主アンカーは**非会心・非急所hit**）／**hit数を記録**（C29連撃: 通常攻撃アンカーは1hit標本のみ採用）／**表示はceil規約**／**HP%併記**（旺盛はHP50%以下で消失）／記録は `data/record_skeleton.md` を複製した `data/trialNN.md`（メタヘッダの「測定メニュー」に M1/M2a/M2b/M3/M4 を記入）。

### M1. 無アビ素走（最優先・C25 baseline分離の決定打）
- **目的**: バフゼロアンカー＝「baseline不足」と「ターン跨ぎ成長不足」を回帰でなく**直接観測で**分離。
- **手順**: アビを一切押さずターン終了のみで2〜3T。T1攻撃フェイズ=全員初期ゲージ100でフルバースト（バフ無しバースト本体×5＋追加ダメ＋ストリーク）。T2以降=ゲージ<100キャラの**素の通常攻撃**（hit数つき）。
- **fitでの使い方**: バフ項0＝残る係数は configB ギア（既知）と baseline のみ。非会心非急所hitなら未知数は実質 baseline スカラ1個。
- **注意**: 敵フェイズ被弾でHP減（旺盛変動→HP%記録）。2走目以降は撤退→再入場でリセット。ヘカテー反撃が出たら値を記録し押下計に混ぜない。

### M2. judg 単独（C31 加算/乗算の判別＋C30 per-hit cap）
- **M2a（装備そのまま）**: 戦闘開始直後・他のバフ無しで judg を最初に押し、**ph0 の10hit個別値**を全記録。次に droid 設置→反応N回後に judg（db.dmg=+3%×N の増分観測）。
  - 判別: 乗算なら hit ∝ 3×(1+abi_dmg+0.03N)、加算なら hit ∝ (3+abi_dmg+0.03N)。N の2水準で傾きが分離（abi_dmg は configB 値を使用）。
  - per-hit cap: 10hit が同値頭打ちなら cap 飽和シグナル（C30 per-hit cap 案の直接証拠）。
- **M2b（任意・検出力最大）**: エラボレイト持ち武器を外し abi_dmg を下げて M2a を1走 → abi_dmg 2水準比較で判別確定。**終了後に装備復元＋変更内容をtrialメタヘッダへ転記必須**。
- **注意**: judg フェーズは戦闘通算連続（C23）＝開始直後の judg は必ず ph0。2押し目以降のフェーズも記録。

### M3. 旺盛スタック（C32 の100%超え実在確認）
- **設計（最小交絡）**: **ヘカテーの通常攻撃を「ムーンコード有/無」で比較**。ムーンコードは vigor+0.3552 と crit_rate+50% のみ＝**非会心マークhitに限れば動く変数が旺盛だけ**（absolute はアサルト/バーストダメも同時に動くため不適）。
- **手順**: HP100%維持・他の旺盛ソース（absolute/legend）が**切れている**状態で、(a)ムーンコード無しの通常攻撃 → (b)ムーンコード有効中（ヘカテー自身アビ累積12毎・持続2T）の通常攻撃。
- **判別**: configB のギア旺盛を Gv とすると、2段capが正なら (b)/(a)=(1+Gv+0.3552)/(1+Gv)、一律100%capが正なら min クランプで比が潰れる（configA 値 Gv=0.6876 なら ×1.21 差。**configB の Gv で期待比を事前に再計算してから実測**）。

### M4. バーストcap+500%（C34・優先度低＝検出力が低い）
- absolute×3 等を積んでバースト本体を比較（cap実在なら合計5.0で頭打ち）。ただしバースト本体は減衰深部（slope0.10）＝増分の1/10しか出ずロールRNGと同オーダー。**単独fitはせず「実装＋M1/M2との整合検証」で閉じる**。

### M5. ゲージ読み（C24・記録様式の拡張のみ）
- record_skeleton の任意欄（敵フェイズ前後ゲージ・ヘカテーCDリキャスト発生押下#）を各M走で可能な範囲で記入。専用走は立てない。

### 追撃cap（C5/C3）— 新規取得は原則不要
- sim03 成分アンカー（ロボ追撃1hit 実機1.58M→2.26M漸増 vs sim≈0.98〜1.01M飽和／追加ダメ 実機1.84M〜6.51M vs sim0.55M〜2.0M）で入力十分。不足時のみ: アンプリファ有/無のロボ追撃比較（+10万フラット分離）・序盤/終盤の追撃値（rawがcapを押し破る点の特定）。

## フォルダ構成・分析ワークフロー（テンプレ標準・sim03以降の新構造）

| パス | 内容 | 責務の境界 |
|---|---|---|
| `data/config.json` | **基本情報JSON（=configB）**＝編成・押し順・敵・GEAR・per-char表示ATK等を全記録 | 一次情報。手を加えない |
| `data/configB_gear_panel.md` | 装備パネル転記＋GEAR整合検証（§2-2） | 一次情報 |
| `data/record_skeleton.md` | **記録スケルトン（コピー原本）**。複製して `trialNN.md` を作る | 様式定義。sim内全trialで統一 |
| `data/trialNN.md` | **実機データ原本**（複製・加工せず。**複製とpushはユーザーが行う**） | 一次情報 |
| `analysis/per_trial/trialNN_{quant,quali}.md` | 単trial中間集計（trialNN.md 1本のみ入力） | trial横断は書かない→rollup |
| `analysis/{quantitative,qualitative}_analysis.md` | trial横断rollup（per_trial全trial入力） | 生trialを再オープンしない |
| `analysis/integrated_analysis.md` | 統合（両rollupのみ入力）＝Cx遷移・モデル修正判断・golden影響・次アクション | 新規集計を持ち込まない |

> 分析は `trial → per_trial → rollup → integrated` の map-reduce（コンテキスト有界化）。命名は `trialNN.md`／`trialNN_quant.md`・`trialNN_quali.md`（NN 2桁で1:1）。
> sim04 特記: trial は測定メニュー横断で通し番号（例 trial01=M1走1・trial02=M1走2・trial03=M2a走1…）。メニューIDはメタヘッダで判別し、rollup はメニュー別に層別集計する。
