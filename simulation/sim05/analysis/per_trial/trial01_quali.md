## 1. ★ 測定設計の想定外 ── M2 は「全成分が1ターンに凝縮」しなかった

[simulation/sim05/README.md](../../README.md) §4.8 は M2 の狙いを
「**T1 撃破＝全成分が1ターンに凝縮し、本体/追加ダメのペアが十数点取れる → C40 の形**」と書いていた。

**半分当たり、半分外れた。**

| | 結果 |
|---|---|
| ✅ 当たり | **本体/追加ダメのペアが 12点**取れた（4キャラ・同一押下＝交絡ゼロ）。C40 の主データとして機能した |
| ❌ 外れ | **T1#41 で撃破した＝攻撃フェイズにもターン終了処理にも到達していない**。∴ **betaia（C41）・DOT・反撃（C45）・バーストストリーク・攻撃フェイズのバースト5人分が1つも取れていない** |

**★構造的な理由**: キャスパリーグは HP 4億で、この編成の**アビリティ押下だけで 102% 削れる**。
「全力で押す」と**攻撃フェイズより先に死ぬ**。∴ **M2 の設計では turn-end 成分は原理的に取れない。**

**申し送り**:
- **ターン終了時成分は M4 が唯一の在庫源**（README §4.8 の想定どおり）＝**M4 は省略できない**。
- 攻撃フェイズ（FB 5人＋ストリーク）を取りたいなら、**M3 の「1ターンだけバースト」走がその役も兼ねる**
  （ボタン OFF で溜め → ON で1ターン）。M3 の記録に **FB 行を必ず入れる**こと。
- あるいは **M2 を宿儺（HP 9.8億）でもう1本**取れば FB まで到達する（ただし障壁・アビ上限が戻る＝交絡が増える）。**推奨しない。**

## 2. 実機の押し順（定石）── 「バフ9手 → ダメージ32手」

実機の押下列（41手）:

```
[1-9]   puvoir absolute divinus legend legend knights miti pike roy      ← 黄/青のみ・ダメージゼロ
[10-24] holy holy judg(ph0) effond sleur judg(ph1) judg(ph2) elegant
        holy elegant_re judg(ph0) elegant_re effond holy judg(ph1)       ← 火力の本体
[25-27] puvoir sleur miti                                                ← 途中で1度だけバフを挟み直す
[28-41] judg(ph2) elegant_re alone holy alone puvoir sleur effond
        consort factor legend miti holy alone                            ← 締め（consort/factor は最後尾）
```

**観測**:

1. **開幕9手はダメージを一切出さない**。`pike`（ナポ3・確実会心）と `roy`（ナポ1）を**バフ側で先に置く**のが実機の型。
   ⚠ [simulation/sim05/analysis/per_trial/pre-trial_quali.md](pre-trial_quali.md) §6 の定石と**同じ形**＝2走で再現。
2. **`consort`（bc≥20 で2hit）と `factor`（bc≥10 で全体CD-1）は 36/37 手目＝ほぼ最後**。
   tier が乗るまで待つという定石が実機側に明確にある。
   ⚠ 現行の静的スコアは「tier が乗るほど終盤寄せ」を持つので**この2つは一致方向**。
   一方 pre-trial quali §6 が指摘した「`pike` の『貯まらなそうなら最速』」は本走でも **8手目＝最速級**で押されており、
   **シムの静的スコアに無い挙動**であることが再確認された（C38 依存の未実装項目）。
3. **`puvoir` / `sleur` / `miti` を 3回ずつ**（1/25/33・14/26/34・7/27/39）＝**CD が明けるたびに即座に押し直す**。
   バフの維持が押し順の骨格になっている。
4. **`judg` は 6回で ph0→ph1→ph2 を丁度2周**（#12 ph0 / #15 ph1 / #16 ph2 / #20 ph0 / #24 ph1 / #28 ph2）。
   **★C23（ジャッジ3フェーズ循環は戦闘通算・ターン毎リセットしない）が、開始 ph0 から連続で回る形で再現している。**
   本走は T1 のみなので「ターンをまたぐか」は検証していないが、**ターン内の連続性は確定**。

## 3. 記録様式（`record_skeleton` 2026-08-05 改訂版）の効き

**★改訂は効いた**。前回（pre-trial）に対して決定的に良くなった点:

| 項目 | pre-trial | trial01 | 効果 |
|---|---|---|---|
| **契晶を押下ごと** | 無し（§2 が全ターン空欄） | **41手すべてに記入** | **C42 の押下単位の検証が初めて可能**になった |
| **本体/追加ダメを別行** | あり | あり（12ペア） | C40 の主データ。**これが無いと走が丸ごと無駄**（skeleton の警告どおり） |
| judg フェーズ列 | あり | あり | C23 の確認に直結 |
| バーストボタン ON/OFF 欄 | 無し | **「常時ON」と明記** | C46 の影響下かどうかが一意に決まる |

**⚠ まだ埋まっていない / 埋められなかったもの**:

| 欄 | 状況 | 判断 |
|---|---|---|
| §2 ターン毎スナップ（HP%・**ゲージ5人分**・味方HP） | 全欄空欄 | **T1 ミッドターン撃破のため「ターン終了時」が存在しない**＝記入不能。ユーザーの説明（§5）は妥当 |
| §1 ターン終了ブロック（DOT・反撃・betaia・holy） | 空欄 | 同上・原理的に発生していない |
| §3 の consort 表示ダメ／闘気／ベタイアの表 | 空欄（値は §1 にある） | **重複欄**＝§1 に書かれていれば足りる。**skeleton から重複を減らす候補** |
| 会心/急所 | 全行「すべて」 | **非会心アンカーが1つも無い**＝C3/C5 が欲しがっていた「非会心の飽和追撃」は本走から取れない |
| §2「同ターンに何回まで押せたか」 | `holy=5` と記入されたが**押下ログでは6回**（数え間違い・ユーザー確認済） | **この欄は押下ログから機械的に数えられる**＝人が数え直すと誤りが入るだけ。**skeleton から削るか「自動集計」と明記**するのが妥当 |

**★ゲージについて（C24）**: 「1ヒット +10」の検算は**ゲージ列が無いと成立しない**。
本走は総和が HP% と 2.0% で整合しているので転記漏れの疑いは薄いが、
**ミッドターン撃破の走でも「撃破直前のゲージ」は読める**はずなので、
**§2 に「撃破時点の値でよい」と明記する**のが skeleton の改善点。
