## 0. なぜ過去データが効くのか

pre-trial（configC v3）1本では、**cap と raw が同時にしか動かない**ため
「cap 構成 / slope / `calib_burst`」を分離できなかった（`per_trial/pre-trial_quant.md` §10.5）。
過去 sim は **GEAR が違う**＝ **cap 水準が違う**ので、この共線性を破れる:

| | GEAR `burst_cap` | GEAR `burst_dmg` | 減衰の深さ raw/cap（平均） | バースト本体 n |
|---|---|---|---|---|
| **configA**（sim03 D走） | **1.98** | 4.86 | **1.90** | **132** |
| **configC v3**（sim05 pre-trial T1・非アリアン） | **2.34** | 7.10 | **3.32** | 11 |

さらに **同一 FB 内のキャラ間比**はパーティバフが約分されるので、**バフ量を知らなくても使える**
（ユーザー懸念「正確なバフ量まで含めると確度が落ちる」への回答）。

⚠ **sim04 の trial01〜03（無アビ素走）はバースト式には使えない**。シムは**通常攻撃によるゲージ上昇を
モデル化していない**ため、アビ0手ではバーストが発生しない。sim04 のあのデータは `calib_na` 用（通常攻撃）である。

## 2. ② ★ `calib_burst` は config 非依存の単一スカラでは成立しない

現行モデル（`slope=0.10` / `calib_burst=2.07`）のまま、バースト本体の 実機/シム を config 別に見る:

| config | n | 実機/シム本体 | CV | → 必要な `calib_burst` |
|---|---|---|---|---|
| **configA**（sim03） | 132 | **0.707** | 12.9% | 1.46 |
| **configC v3**（pre-trial） | 11 | **0.800** | 9.2% | 1.66 |

**13% 食い違う**。∴ **`calib_burst` を1個のスカラで直す方針は成立しない**
（＝`per_trial/pre-trial_quant.md` §10.2 の「2.07→1.66」は configC 限定の値だった）。

**方向が情報を持つ**: 減衰が**深い** config（configC・raw/cap 3.32）ほど実機/シムが**大きい**
＝ **シムは深いところで削りすぎている＝ slope が小さすぎる**。

## 3. ★ 犯人は `decay_burst.slope` ── 0.10 は小さすぎる

`slope` を掃引して、2 config の残差が一致する点を探した:

| slope | configA 実機/シム | configC 実機/シム | 食い違い | 共通 calib 候補 |
|---|---|---|---|---|
| 0.05 | 0.734 | 0.866 | 16.4% | 1.66 |
| **0.10（現行）** | **0.707** | **0.800** | **12.3%** | 1.56 |
| 0.16 | 0.677 | 0.734 | 8.0% | 1.46 |
| 0.25 | 0.637 | 0.654 | 2.6% | 1.34 |
| **0.30** | **0.617** | **0.617** | **0.1%** ← 一致 | **1.28** |
| 0.40 | 0.582 | 0.555 | 4.7% | 1.18 |

**`slope=0.30` で2つの config が 0.1% まで一致する**。

### 3.1 独立検証 ── 残差と「減衰の深さ」の相関

slope が誤っていれば、残差は **減衰の深さ（raw/cap）と系統的に相関する**はず。
これは **config を跨がなくても効く内部検証**（config 間一致とは別の基準）:

| 設定 | 実機/シム（全体 n=143） | CV | **r（残差 × 深さ）** |
|---|---|---|---|
| **現行 slope=0.10 / calib=2.07** | 0.714 | **13.1%** | **r=0.675** ← 強い系統誤差 |
| slope=0.30 / calib=1.28 | 0.938 | **9.0%** | r=0.185 |
| **slope=0.40 / calib=1.20** | 0.580 | **8.7%** | **r=−0.001** ← 相関が消える |

- **CV が 13.1% → 8.7〜9.0% に改善**（実機のばらつき水準に到達）。
- **相関 r が 0.675 → ほぼ 0**＝ **深さ依存の系統誤差が取れた**。
- 2つの基準が指す値は少し違う（**config 間一致 → 0.30 ／ 相関ゼロ → 0.40**）。
  ∴ **単一 slope の線形減衰でもまだ完全ではない**（`decay_na` のような**多段減衰**の可能性）。
  ただし **どちらの基準でも現行 0.10 より大幅に良い**ことは動かない。

### 3.2 キャラ別残差（slope=0.30 / calib=1.28）

| owner | n | 実機/シム本体 | CV（現行 0.10 のとき） |
|---|---|---|---|
| edison | 10 | 0.893 | 5.6%（8.9%） |
| **yamato** | 40 | **1.003** | 11.2%（11.9%） |
| hecate | 29 | 0.916 | 5.2%（12.6%） |
| tetra | 28 | 0.909 | 7.1%（10.1%） |
| elaine | 35 | 0.919 | 4.3%（11.0%） |

- **キャラ別 CV が軒並み半減**（elaine 11.0→4.3%・hecate 12.6→5.2%）＝ slope 修正の効果は本物。
- ⚠ **yamato だけ他より +9% 高い**（1.003 vs 0.89〜0.92）。
  アリアン（configC で**シム過大** ×1.37）と**逆向き**だが同じ場所＝
  **キャラ固有のバースト強化（`burstBonus` / `burstCapSpecial`）の扱いに個体差がある**という共通シグナル。

## 5. 結論と、実装前に残る宿題

**確定したこと**:

1. **エジソン編成の手数モデルは健全**（340手すべて再生）。C42 は新編成固有。
2. **`decay_burst.slope=0.10` は小さすぎる**。**0.30〜0.40** で、①2 config の残差が一致し
   ②残差と減衰の深さの相関が消え ③CV が 13.1%→8.7〜9.0% に改善する。
3. **`calib_burst` は slope とセットでしか決まらない**。slope=0.30 なら ≈**1.28**、slope=0.40 なら ≈**1.20**。
   「2.07→1.66」は **configC 限定の見かけの値**だった。
4. **キャラ固有のバースト強化に個体差**: アリアン（過大 ×1.37）／ヤマト（過小側 +9%）。

**実装前に残る宿題**:

| # | 項目 | 理由 |
|---|---|---|
| 1 | **slope 0.30 と 0.40 のどちらか（あるいは多段減衰か）** | 2つの基準が別の値を指す＝単一 slope では説明しきれない残差がある。**第3の cap 水準**があれば決まる（sim04 configB は 2.016 で configA 1.98 に近く、レバレッジが小さい） |
| 2 | **減衰外フラット項**（`roy_burst_frac[3]=1.00` 等） | 依然未検証。実機本体の 17〜50%（configC）を占め、**cap/slope をどう直しても動かない**独立項 |
| 3 | **キャラ固有バーストバフ**（`burstBonus` / `burstCapSpecial`） | アリアン／ヤマトで逆方向の個体差。M2/M3 で per-char に切り分ける |
| 4 | **golden 再fit の規模** | slope と calib の両方が動く＝**edison fixture が大きく動く**。M2〜M6 の結果と合わせて**1回で**入れる |

⚠ **本分析では production を一切変更していない**（golden 3/3 不変）。
