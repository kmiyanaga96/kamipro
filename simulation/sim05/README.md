## 4. 設計

### 4.1 ナポレオン押し順ヒューリスティック（cands.s）

**Q1 解決（2026-07-22・ユーザー確定＝一次情報が正）**: アビ番号↔キーは napoleon.md §1.2 が正＝**1アビ=roy / 2アビ=pike（buffCount≥15で確実会心）/ 3アビ=consort（≥20で2hit）/ 4アビ=factor（≥10で全体CD-1）**。移行README ユーザー所感の「2アビ＝≥10ゲート」は番号の取り違えで、**ゲート値は一次情報（pike≥15・factor≥10）を採る**。所感の定性的な意図（短縮レバーは**CD中アビが最多の位置で**＝早撃ちしない・ダメ/tier系は後半）はキーを正して踏襲:

- `factor`（4アビ・≥10で全体CD-1）: **ifishant と同型の動的スコア＝CD中アビ数が最多のターンで浮上**（`s=(CD中数)²`）。≥10 は CD-1 が効くゲートで下回れば低優先。**⚠『≥10で最速』は誤り（2026-07-22 ユーザー訂正）**＝短縮効果ゆえ**早撃ちは機会損失が大きい**、CD中アビが最も多い位置で打つのが理想（イフィシャントの打ち方を踏襲）。
- `pike`（2アビ・≥15で確実会心）: **buffCount がゲート(15)付近で高スコア＝会心を早く確定**させ後続を底上げ。
- `roy`（1アビ・全攻撃ダメプラス tier）・`consort`（3アビ・赤ダメ ≥20で2hit）: **終盤寄せの低〜中スコア**（バフ数が乗るほど tier/hit が伸びる）。
- 実装は各 cands に `s:` を付与するのみ（エンジン本体・探索ロジックは非改修）。**golden 非影響**（ナポレオンは golden 編成に不在）。buffCount 依存スコアは静的スコアの動的評価（cands.s を関数化 or exec前フックで参照）が要るか要確認＝現行 cands.s が定数のみなら小改修。**✅実装済み（cands.s は buffCount 動的関数）**。
- ⚠**buffCount 過大（tier ゲートが T1 から全到達＝無効化）の sim側分解は確定＝`buffcount_sim_side_diag.md`**（`arian_bplus` 等の内部累積スタックが主因）。**閾値の差替/再スケールは較正走で実機 tier 実発動ターンを取得して照合後**（TODO①）。

### 4.2 アリアン回数制限×短縮の条件付き+1

ユーザー所感§2:「アリアンのアビ回数制限は、自身の短縮効果／ifishant／ナポ4アビ(factor) の CD 短縮で**上限超過発動**が可能」＝**エレインの ifishant リキャスト（`ifAlone/ifLegend/ifKnights/ifPactcore`）と同型**。

- **Q5 解決（2026-07-22・ユーザー確定）**: 上限超過は**1回に留まらない**＝実機で**1アビ(holy=ホーリーターボ)が1ターン最大5回ほど**発動した例あり。∴ +1 枠は**単一フラグでなく累積カウンタ**（短縮ソースの発火数だけ上限を押し上げる）。
- 設計: `holy`（手動2/T）・`elegant_re`（回数ゲート）の上限を、**短縮ソースが「クォータ消化済みのアリアンアビ」に作用した回数だけ引き上げる累積カウンタ**（`arian_holy_plus` 等・エレイン if枠の数値カウンタと同型）で表現。C21 の教訓（発動可能状態のアビは増やせない・クォータ消化済み/CD中のみ復活）を踏襲しつつ、**複数回の上限超過を許す**（Q5）。holy は手動2＋短縮由来の追加で同ターン多数回（実機で〜5回）撃てる状態を再現。
- 短縮ソース: アリアン2アシ（光3バースト毎の自CD-1）・ナポ factor（全体CD-1）・イフィシャント系が編成にあれば同様。**実機の発火優先順・具体例**（どの短縮がどのアビを何回復活させたか）は G4 の走で裏取りし、カウンタ増分規則を確定。
- state: エレイン if枠と同型の数値カウンタ（`arian_holy_plus` 等）を宣言し、`guard` で参照。
- ⚠**HP参照項（A9・HP80%ゲート）は現状フルHP前提で常時発動**。厳密化は**未確定Phase(i)＝生存/現在HPモデル**以降（arianrhod.md 注記どおり保留）。

### 4.3 追撃較正（C3/C5・本丸）

- **対象成分**（arianrhod.md A1 で別枠2本確定＋エジソン系とは別）: ①アリアン バースト効果「追加ダメージ」 ②1アシ トランジェントマイト「追撃」 ③（参考）エジソン英霊武器追撃は本編成では英霊がナポなので不在＝**交絡が1つ減る**。現実装は①②とも 3倍/cap50万（アビ枠）で近似。
- **sim04 で判明済みの数値**: 追撃系は成分別 実機/sim ×2.3〜6.9・**非決定的 fit**（会心/急所RNG が乗り単発 raw を直読できない）で残差保留。
- **sim05 での解き方**: sim04/C25 と同じ「**非会心・非急所の非飽和アンカー**」原則。この編成は追撃が支配的なので、追撃単発が総ダメに効く＝アンカーが取りやすい。走の設計:
  - **モード D（全深測定・撃破まで）×5走**を基本（sim03 と同型・イベント列決定性を利用して5走で追撃成分を平均）。较正ボスの affinity/隠れ耐性がクリーンなこと（§4.4）が前提。
  - 各走で**追撃ヒットの会心/急所マーク**を記録（record_skeleton に列を用意）＝マーク一致ヒット間で raw を平均し、成分別（①②）の cap/slope を fit。
  - fit 順: **C5（追撃 cap レベル）→ C3（追撃式・合流）**。sim04 の judg/burst と同じく pre-cap raw に乖離が局在するか（深飽和一致か）をまず確認。
