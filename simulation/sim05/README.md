### 2.3 実施順と依存の原則

**実施順＝`M1 → M2 → M3 → M5 → M4 → M6`**（M7 は全走に相乗り）。

- **原則は「カウントで閉じる → 比で閉じる → 絶対で閉じる」**（変数最小の原則）。
  この原則だけなら M5（カウント）が M3（比）より先だが、**ユーザーが M3 に着手済みなので実順序は M3 が先**。
  **M5 はダメージモデル非依存**なのでどちらの順でも成立する。
- **比で閉じる型の強さ**: C40 の根拠「追加ダメ/本体 = 0.51〜0.77」は `final_dmg`・敵 def・ギアが
  **共通因子として約分される**ため、**A7 も敵 def も未確定のまま既に成立している**。
- ⚠ **C40/C41/C44 の実装は M2〜M6 が揃うまで着手しない**（部分的に直すと較正スカラが誤差を吸収する）。

## 4. 実機走フローと測定メニュー

> **通称「I走」（アイソレーション走）**。障壁もアビ上限も無いので、**意図的に手を抜いて1成分だけを動かす**設計ができる。
> **全力で回すのは M2 だけで、残りは「押さないこと」で交絡を落とす。**
> **ID 接頭辞は REPO_STANDARDS §3 に従い `Mx`**（単独測定メニュー・sim 内連番。ad-hoc な新接頭辞は発明しない）。
> trial は**メニュー横断の通し番号**で、`trialNN.md` のメタヘッダに測定メニューID を書いて判別する。

### 4.1 全走に共通する前提

- **敵＝キャスパリーグ `cath_palug`**（HP 4億・def 10・闇属性＝光有利 ×1.5・**障壁なし・アビ上限なし**）。
  ライトレジストは光属性*以外*が対象＝**我々の光攻撃に隠れ耐性は掛からない**。
- **記録様式は `data/record_skeleton.md` が正**（複製して `data/trialNN.md` を作る。**複製と push はユーザー**）。
- **押した順を必ず記録**（フリー押しでよいが、順序の記録は必須要件＝これが無いとリプレイできず較正が成立しない）。
- **⚠ バースト発動ボタン OFF で「溜める」が実機の選択肢**（`gamedata/md/その他/attack_phase.md`）。
  M3/M4 はこれを使う。**シムは OFF を持たない（C46）**＝そのターンは C46 の影響下にあると明記して測る。

### 4.3 各メニューの手順

#### M3 ── バースト「追加ダメージ」の定式化（C40）★実機測定中

**狙い**: 追加ダメ ÷ 本体 が**バフ量に依存するか**（本体連動 or 別式）を分離する。**C40 は編成横断＝edison golden にも効く**。

**設計＝バフ別 ablation 梯子**（ユーザー確定 2026-08-06）: 「**バフ0本 → 特定のバフ1本 → 2本 …** を、**各バフに対して**」。

> **なぜ対照（contrast）が要るか**: 追加ダメも本体も**同じバフ量の関数**なので、**全部盛りの1点**では
> `追加 = f(本体)` と `追加 = g(バフ量)` が区別できない（共線）。**trial01 がまさにこれで止まった**
> ＝12点あって r=0.688・回帰 `追加 = 0.302×本体 + 5.38M` の切片が平均の 54% を占めるのに、
> **本体連動か別式かを決められなかった**（`analysis/per_trial/trial01_quant.md` §4-2）。
> **データ量を増やすと分散は減るが、識別できない量は何点取っても識別できない。**
> ∴ **ablation（1本ずつ足す）が正解**で、**volume は各設計点の繰り返し（n 稼ぎ）に充てる**。

**手順**: **バースト発動ボタンを OFF で開始**しゲージを溜める → 下表の順でバフ本数を変える →
**ボタン ON にして1ターンだけバースト** → 終了。
⚠ **黄アビ自体が BG を付与する**（`legend`+10 / `sleur`+15 / `absolute`+20）＝バフを増やすとゲージも増える。
**ボタン OFF で溜めておけば「バフ量」と「バーストの有無」を分離できる**（これが M3 の肝）。

**★ablation の順**（先に取ると情報が多い順）:

| 順 | 走 | 何が決まるか |
|---|---|---|
| 1 | **バフ0本**（素のバースト）×複数回 | **基準点**。他のすべてがここからの差分＝**最初に n を稼ぐ価値が最も高い** |
| 2 | 0本 ＋ **`knights` だけ** | ★**C40 の関数形が1対比較で決まる**（`burst_dmg_nights` +20%＝**バースト枠のみ**＝**本体だけを動かせる唯一のレバー**）。追加ダメも +20% 動く→**本体連動**／動かない→**別枠** |
| 3 | 0本 ＋ **`puvoir` 1 stack** | ★**クラスタ①の検証**（アビ枠 cap-UP の共通欠落 ×1.48）。**1 stack で足りる**（下記） |
| 4 | 0本 ＋ `absolute` / `legend` / `miti` / `roy` / `pike` を各1本 | 各枠の寄与を個別に確定 |
| 5 | 0本 ＋ `sleur` / `factor` | **ダメージは変わらないはず**＝**変わったら未モデル化の発見**（安い検証） |
| 6 | 2本組み合わせ（とくに `absolute`＋`puvoir`） | **枠が加算か乗算か**＝1本ずつの結果から予測して答え合わせ |
| 7 | 全部盛り | 外挿の最終検証点 |

⚠ **`pike` を入れた走は以降ずっと会心・急所が乗る**（bc≥15 で確実会心）＝**`pike` は梯子の後ろに置く**。
⚠ `absolute` は cap +20% ＋ バーストダメ +30% ＋ アサルト＝**3枠同時**＝単独では分離に使えない。

**記録**: 攻撃フェイズの**キャラごとに「バースト本体」と「追加ダメージ」を別行で**（合算しない）。
★**FB 行（攻撃フェイズ）とバーストストリークを必ず記録**＝**M2 が T1 撃破で攻撃フェイズに到達しなかった**ため、
**ストリークと5人バーストの取得機会が M3 しか残っていない**（`analysis/per_trial/trial01_quali.md` §1）。

**読み方**: 比が梯子を通じて一定 → 本体連動（係数を1つ直せばよい）／バフ量とともに動く → **別式**（定式化からやり直し）。

<details>
<summary><b>★`puvoir` は 1 stack で足り、バーストも 1 回も要らない</b>（ユーザー指摘 2026-08-06 への回答）</summary>

**ユーザー指摘**: 「puvoir のリキャストにはバーストを複数回行う必要があり、その場合バースト効果で余計なバフが混入する。
1 stack までしか純粋な効果量は測れなそう」。

**① 結論: 1 stack で足りる。**

**② ⚠ Claude Code の前版の記述を訂正**: `puvoir` を「上限UP のみ」と書いたのは**誤り**。
一次情報（`gamedata/md/神姫/hecate.md` §1 アビ1）＝「味方全体の**光属性攻撃**・**ダメージ上限**UP(累積可)」
＝シムも **`elem_puvoir=+0.15`/stack（raw）と `cap_puvoir=+0.06`/stack（cap）の2枠**を持つ。**純粋な cap レバーではない。**

**③ それでも分離できる**: cap は**ほぼ等倍**で効き、raw は **slope 0.04 倍**に潰れて効く。
∴ **cap/raw 比が違う成分には2つの効果が違う配合で載る**＝**2成分以上を読めば連立で解ける**:

| 成分 | Δout（1 stack・シム予測） | 内 cap 由来 | 内 elem(raw) 由来 | cap 由来の割合 | 実機hit/押下 |
|---|---|---|---|---|---|
| **holy 8hit** | **+3.11%** | +1.89% | +1.22% | **60.8%** | **8** |
| **judg ph0** | **+2.98%** | +2.07% | +0.91% | **69.4%** | **10** |
| consort | +2.72% | +2.13% | +0.60% | 78.1% | 2 |

配合比（elem 感度 ÷ cap 感度）が 0.258 / 0.176 / 0.112 と散る＝**2成分あれば別々に推定できる**（見積り＝`node tools/exp_puvoir_lever.mjs`）。

**④ ★バーストは1回も要らない**: `holy`（黄）・`judg` ph0（赤だが ph0 はバーストではない）・`consort`（赤だが
**`burstTrigger` フラグを持たない**）は**バーストボタン OFF のまま押せる**。
∴ 「puvoir 無し → 1 stack」の2条件を**バーストを1度も発生させずに**比較できる。
⚠ **`burstTrigger` を持つのは `effond` と `elegant` だけ**＝この2つと `alone`／`judg` ph1 を踏まなければバーストは起きない。
⚠ `judg` は押すたびに ph0→ph1→ph2 と巡る＝**1走で judg は1回だけ**（ph0 のみ）に留める。

**⑤ 精度は足りる**: holy 1押下8ヒットの**ヒット間 CV は実測 1.04%**（trial01 #10）。
∴ 1押下の平均の SE は 0.35%、3押下ずつなら差の SE は 0.29% ＝ **効果 3.11% は約 10σ**。
⚠ ただし**バフ状態を揃えることが絶対条件**（trial01 では holy の押下平均がターン内で 19% 上昇している）。**puvoir 以外は完全に同一手順**にする。

**⑥ リキャストにバーストが要るのか**: シム定義では `puvoir` は CD 2・効果6T＝ボタン OFF で溜めている間に
T1/T3/T5 と 3 stack まで積めるはず。⚠ **実機の挙動が正**だが、④⑤ により **1 stack で完結する**ので問題にならない。
</details>

## 付録A ── 経緯の保全（★現在値として引用しない）

### A.1 追撃較正 C3/C5 の降格（2026-08-03）

従来「追撃 実機比 ×2.3〜6.9」と見えていたのは**①バースト効果「追加ダメージ」を追撃と混同していた**ため（→ **C40**・編成横断）。
純粋な追撃（②1アシ トランジェントマイト）は ×1.29〜1.55・T1 乖離寄与 1.2%＝
**「②の cap を実効117.5万→160万級へ」という小さく確定的な作業**に縮小した。
⚠ アリアンの①と②は `arianrhod.md` A1 で**別枠2本**と確定しているが、シムは**同一値で2回加算**している（→ **C47**）。

### A.2 「非会心・非急所アンカー」原則の retire（2026-08-06・C49）

当初の解き方は「**非会心・非急所の非飽和アンカー**」でヒットを選別して raw を平均する設計だった。**retire した理由**:

- **非会心アンカーは今後ほぼ取得できない**（ウェポン構成上・かつ一次情報 `damage_frames.md` ⑨
  「会心は**有利属性相手でなくとも発動する**」＝**敵を変えても逃げられない**）。
- **非急所アンカーは「非有利属性の敵」でのみ取得できる**（同 ⑧「急所は**有利属性相手でしか発動しない**」）が、
  引き換えに**属性値枠（`DMG.affinity`）が推定値になる**＝誤差源を1つ交換するだけ。
- ⚠ さらに **「全ヒット急所表示」＝「全ソースが発動」ではない**（表示は二値・実効倍率は加算で可変）
  ＝**有利属性の走からは急所枠を同定できない**。

∴ 代替＝**「常時会心・常時急所を前提にシム側も確定発動として評価する」**。
⚠ ただし**優先度は低い**（急所枠は raw に乗るが、現状は全成分 cap 拘束で raw の効きが slope 0.04 まで潰れている＝乖離の 5.4% 相当）。
**クラスタ①（cap）を直した後に効いてくる**。詳細は CALIBRATION_ANALYSIS **C49**。

### A.3 絶対値の乖離は T1 に局在している（起票時の記録）

宿儺の**ターン増分**に直すと乖離が T1 だけに集中していた:

| | T1 | T2 | T3 |
|---|---|---|---|
| 実機 増分 | **54%** | 22% | ≧24% |
| 比（実機/シム） | **×2.43** | ×1.07 | ≧×0.92 |

**一律スカラでは説明できない**（T2/T3 はほぼ一致しているので、一律スカラを入れると T2 以降が過大になる）。
**T2 が ×1.07 で合っていること自体が情報**＝**≈19手の条件ではダメージモデルはほぼ正しい**。
**方向は「シムが過小」で確定**（実機はフリー押し・シムはビーム最適＝モデルが正しければシム ≧ 人間のはず）。

> ⚠ **本節の仮説表は pre-trial 分析で決着済**: 仮説2「T1バースト過小」は**逆向きに否定**（→ C44）、
> 仮説4「ベタイア cap 過小」は**確証**（→ C41）、仮説3「障壁 rate」は**向きのみ支持**、
> 仮説1「cap 19」は**「30手で自然枯渇」が誤り＝実機の押し順を強制すれば 39手通る**と判明。
> ⚠ 当時の「シム 増分 22.2%」は **v2 GEAR での測定値＝無効**。現在値は `analysis/per_trial/pre-trial_quant.md`。

### A.4 M1 の手法 ── 過去 sim の在庫の使い方

**閉じたのは slope（現行 0.10 を支持）と「C40 は編成横断」まで**で、**`calib_burst` は閉じなかった**
（configA が要求する ≈1.46 と configC の ≈1.66 が 13% 食い違い、原因未特定）。∴ **手法は有効だが在庫だけでは足りない**。

| 使い方 | なぜバフ量を知らなくてよいか | 在庫 |
|---|---|---|
| **同一 FB 内のキャラ間比** | 5人が**同時刻・同一パーティバフ**で撃つ＝比を取るとパーティバフが**完全に約分される**。per-char 係数（`burst_coef_a/b`・`burstBonus`・`burstCapSpecial`）を**バフ非依存に**同定できる | sim04 trial01〜09 / sim03 trial01〜05 の**全攻撃フェイズ行** |
| **GEAR の違いを使う** | sim03/sim04 は `burst_cap` 等が configC と違う＝**cap と slope の共線性を破れる唯一の在庫** | 同上 |

⚠ **限界**: sim03/sim04 は**エジソン/ヤマト編成＝アリアン不在**。取れるのは**共通構造**であってアリアン固有値ではない。
⚠ **バフ量に依存する fit（絶対値の直接 fit）は在庫データではやらない**こと。

### A.5 較正ボスの選定実測（2026-08-01・宿儺を選んだ根拠）

**実機結果**（HP% は画面から読んだ概数）:

| ボス | 実機 撃破 | 実機 各T終了時 残HP | シム予測 | 実機/シム（累計与ダメ比） |
|---|---|---|---|---|
| ロキ（HP 9.8億） | T2 攻撃フェイズ | T1 36% | T3 撃破 | T1 ×1.37 |
| **両面宿儺（採用）** | **T3 ベタイア** | T1 46% / T2 24% | T5 撃破 | T1 **×2.43** / T2 ×1.78 |

- **両ボスとも被ダメージ 0**（テトラ1アシの T1 無敵＋ヘカテーの反撃）＝**生存ゲートは論点ごと消滅**。
  シムの「常時フルHP近似」も厳密に成立する。
- **採用理由**: clean な測定ターンが **ロキ1 / 宿儺2**＝宿儺が最良。ただし要件の4には届かない
  ＝**複数走で稼ぐ**か**高HPボスの再確認**で補う。
- **較正用途では宿儺の欠点が無害化される**: `abilCapPerTurn:19` の探索不安定性（C37/B1）は**リプレイ突合の較正には無関係**／
  鬼神障壁は **burst 本体と streak にのみ適用＝追撃（abi枠）は無傷**。
  ⚠ ただし**総ダメは汚れる**＝**C25 絶対値の結論はこのボスでは出さない**。
- ⚠ **この選定は 2026-08-03 に2段構えへ改訂された**（§3.3）＝宿儺は**最終検証（G4.9）専用**になった。

### A.6 鬼神障壁の実装（宿儺・G4.9 用）

敵特性 `barrier:{na,burst,streak,abi?,rate}`（`DMG.enemy_barrier`・既定 null）
＝1ヒットが枠別上限超過なら `cap+(dmg-cap)*rate` に軽減。
適用点は**最終ダメの加算点＝burst 本体と streak のみ**（burst の返り値 core は streak 基底に再利用のため
`_decay` 内では畳まず二重cap回避）。registry: na600万 / burst3000万 / streak300万 / abi未設定（＝非軽減）/ rate 0.70。
⚠ **rate の解釈（超過分×rate か全体×rate か）と barrier.abi の有無は実機で確定する**（記録先＝`data/record_skeleton.md` §6）。
