## 4. 設計

### 4.1 ナポレオン押し順ヒューリスティック（実装済み）

アビ番号↔キーは一次情報が正＝**1=roy / 2=pike（bc≥15で確実会心）/ 3=consort（≥20で2hit）/ 4=factor（≥10で全体CD-1）**。

- `factor`: **ifishant と同型の動的スコア＝CD中アビ数が最多のターンで浮上**（短縮効果ゆえ早撃ちは機会損失）。
- `pike`: 閾値付近で高スコア＝会心を早く確定させ後続を底上げ。
- `roy` / `consort`: 終盤寄せ（バフ数が乗るほど tier/hit が伸びる）。
- ⚠**現状これらはすべて機能停止している**（C38＝buffCount 過大で全 tier が T1 から常時到達）。**§4.6 の実機データが前提**。

### 4.2 アリアン回数制限×短縮の条件付き+1（実装済み）

自身の短縮／ifishant／ナポ factor の CD 短縮で**上限超過発動**が可能（エレイン ifishant リキャストと同型）。上限超過は**1回に留まらない**（実機で holy が1ターン最大〜5回）＝**累積カウンタ**で表現。⚠ A9（HP80%ゲート）はフルHP前提で常時発動＝厳密化は未確定Phase(i) 以降。

### 4.3 追撃較正（C3/C5・**2026-08-03 に主題から降格**）

> ⚠ **本節は当初の主題だったが、pre-trial で降格した**。従来「追撃 実機比 ×2.3〜6.9」と見えていたのは
> **①バースト効果「追加ダメージ」を追撃と混同していた**ため（→ **C40**・編成横断）。純粋な追撃（②1アシ）は
> ×1.29〜1.55・T1 乖離寄与 1.2%＝「②の cap を実効117.5万→160万級へ」という**小さく確定的な作業**に縮小した。
> **現在の本丸は C41（betaia cap）／C40（追加ダメージの式）／C44（バースト本体の過大）**（§4.8）。
> 以下は当初設計の保全（「非会心アンカー」原則の破綻メモを含む）。

- **対象成分**: ①アリアン バースト効果「追加ダメージ」 ②1アシ トランジェントマイト「追撃」（arianrhod.md A1 で**別枠2本**確定）。現実装は①②とも 3倍/cap50万（アビ枠）。英霊がナポなのでエジソン英霊武器追撃は不在＝**交絡が1つ減る**。
- **sim04 で判明済み**: 追撃系は成分別 実機/sim ×2.3〜6.9・**非決定的 fit**（会心/急所RNG が乗り単発 raw を直読できない）で残差保留。
- ⚠ **2026-08-03: 「非会心・非急所アンカー」原則は本装備で成立しない**（pre-trial §5＝スティンガー武器＝急所確率UP を
  投入したため**全ヒットが会心・急所**）。代替＝「常時会心・常時急所を前提にシム側も確定発動として評価する」か
  「急所の実効倍率を実機から逆算する」。本trial設計時にユーザーと確定する（`analysis/PROVISIONAL_ANALYSIS.md` §5）。
- **解き方（当初）**: 「**非会心・非急所の非飽和アンカー**」原則。各ヒットの会心/急所マークを記録し、マーク一致ヒット間で raw を平均して成分別に cap/slope を fit。**fit 順は C5（cap レベル）→ C3（式）**。
- **❌ 2026-08-06: 本原則を retire する**（ユーザー申告＋一次情報突合＝**C49**）。
  **非会心アンカーは今後ほぼ取得できない**（ウェポン構成上・かつ一次情報 `damage_frames.md` ⑨「会心は**有利属性相手でなくとも発動する**」＝敵を変えても逃げられない）。
  **非急所アンカーは「非有利属性の敵」でのみ取得できる**（同 ⑧「急所は**有利属性相手でしか発動しない**」）が、
  引き換えに**属性値枠（`DMG.affinity`）が推定値になる**＝誤差源を1つ交換するだけ。
  ⚠ さらに **「全ヒット急所表示」＝「全ソースが発動」ではない**（表示は二値・実効倍率は加算で可変）＝
  **有利属性の走からは急所枠を同定できない**。∴ 代替方針は **PROVISIONAL §5 案(a)「常時会心・常時急所を前提にシム側も確定発動として評価する」**。
  ⚠ ただし**優先度は低い**（急所枠は raw に乗るが、現状は全成分 cap 拘束で raw の効きが slope 0.04 まで潰れている＝乖離の 5.4% 相当）。
  **クラスタ①（cap）を直した後に効いてくる**。詳細は CALIBRATION_ANALYSIS **C49**。
- **⚠ 新仮説: ベタイアの cap 過小**（2026-08-02）。configC でシムの `betaia` は **cap 飽和**（素点 1,213,875 に対し `DMG.betaia_cap`=800,000＝**34%切り捨て**・aura20 で20ヒット/ターン）。実機ではベタイアが**主ダメージ源の一つ**なので、**実機 cap がシムより高ければ C3/C5 と同型の「cap 過小」**。**ベタイア1ヒットの表示ダメージがそのまま実機 cap を与える**＝最も費用対効果の高い取得物。

> **「30手で自然枯渇」が誤り＝実機の押し順を強制すれば 39手通る**と判明（寄与は未定量）。
> ⚠ **下表の「シム 増分 22.2%」は v2 GEAR での測定値＝無効**（`analysis/per_trial/pre-trial_quant.md` §2）。

宿儺の**ターン増分**に直すと乖離が T1 だけに集中する:

| | T1 | T2 | T3 |
|---|---|---|---|
| シム 増分 | 22.2% | 20.6% | 26.0% |

**一律スカラでは説明できない**（T2/T3 はほぼ一致しているので、一律スカラを入れると T2 以降が過大になる）。

**T2 が ×1.07 で合っていること自体が情報**: cap=19 は T2/T3 にも張り付いているのに合っている

### 4.5 鬼神障壁（実装済み・rate は未検証）

敵特性 `barrier:{na,burst,streak,abi?,rate}`（`DMG.enemy_barrier`・既定 null）＝1ヒットが枠別上限超過なら `cap+(dmg-cap)*rate` に軽減。適用点は**最終ダメの加算点＝burst 本体と streak のみ**（burst の返り値 core は streak 基底に再利用のため `_decay` 内では畳まず二重cap回避）。registry: na600万/burst3000万/streak300万/abi未設定（＝非軽減）/rate 0.70。
⚠**rate の解釈（超過分×rate か全体×rate か）と barrier.abi の有無は実機で確定する**（記録先 `record_skeleton` §4）。

### 4.6 tier 観測（C38・buffCount）

シムの `buffCount` は**同一効果の内部スタックを1個ずつ加算**するため実機より大幅に過大＝**T1 で既に bc=34・以降88〜100 で全 tier が常時到達＝tier による切り替えが一度も起きない**（シム側の分解は `buffcount_sim_side_diag.md`）。∴ §4.1 のスコアは定数に張り付いており、**ナポアビ予測探索は本Cxの解決が前提**。

**⚠ 取得方式（2026-08-02 変更）**: 実機UIは**バフの付与先を表示せず効果量のストック表示**＝**アイコン計数は非現実的**（ユーザー報告）。
∴ **各 tier の「効果の成立/不成立」から実機 bc を区間推定する**（例: factor 成立かつ consort 1hit → 10≤bc<20）。4 tier はいずれも外から見える効果を持ち、その大半は取得が容易な**成分別ダメージ・ヒット数・CD表示**に現れる（一覧は `record_skeleton` §3）。
さらに **consort の倍率は一次情報で `2+0.5×bc`＝ダメージ自体が bc の1次関数**＝cap（250万）未到達なら**表示ダメージから bc を直接逆算できる**。

→ 判明後に **(a) `buffCount` を『別種バフ数』へ差替**（累積系を1カウントに畳む）**か (b) 閾値を現行スケールへ再スケール**を決定し、napoleon golden を再fit。

#### 4.8.1 ★ M1 で同時に閉じる ── バースト式の構造パラメータ（過去データの使い方）

> ✅ **M1 は 2026-08-03 に実施済**（結果＝`analysis/m1_history_replay.md`）。**閉じたのは slope（現行 0.10 を支持）
> と「C40 は編成横断」まで**で、**`calib_burst` は閉じなかった**（configA が要求する ≈1.46 と configC の ≈1.66 が
> 13% 食い違い、原因未特定）。∴ 下記の「同一 FB 内のキャラ間比」「GEAR の違い」という**手法は有効だった**が、
> **在庫だけでは足りず M2〜M6 の実機走が要る**というのが結論。以下は手法の記録として残す。

pre-trial で **C44 は係数2つ（`calib_burst` ≈1.66 / アリアン `arian_cap_boost` ≈+30〜40%）まで縮んだ**が、
**slope と cap 構成の分離**と**減衰外フラット項の検証**は1走では原理的にできない
（`analysis/per_trial/pre-trial_quant.md` §10.5）。ここに**過去 sim の在庫**が効く:

| 使い方 | なぜバフ量を知らなくてよいか | 在庫 |
|---|---|---|
| **同一 FB 内のキャラ間比** | 5人が**同時刻・同一パーティバフ**で撃つ＝比を取るとパーティバフが**完全に約分される**。per-char 係数（`burst_coef_a/b`・`burstBonus`・`burstCapSpecial`）を**バフ非依存に**同定できる | sim04 trial01〜09 / sim03 trial01〜05 の**全攻撃フェイズ行** |
| **GEAR の違いを使う** | sim03/sim04 は `burst_cap` 等が configC と違う＝**cap と slope の共線性を破れる唯一の在庫** | 同上（config は各 sim の `simNN/data/config.json` / gear_panel） |

⚠ **限界**: sim03/sim04 は**エジソン/ヤマト編成＝アリアン不在**。取れるのは**共通構造**
（slope・cap 構成・`calib_burst`・フラット項）であって、アリアン固有値ではない。
⚠ ユーザー懸念「正確なバフ量まで含めると確度が落ちる」は上の2つの使い方なら回避できるが、
**バフ量に依存する fit（絶対値の直接 fit）は在庫データではやらない**こと。

**依存順**: M1（無料・先頭）→ M5/M6（**カウントと比だけで閉じる＝ダメージモデル非依存**）→ M2/M3（比で閉じる）→ M4（絶対で閉じる）。
**変数最小の原則**: 「**カウントで閉じるもの → 比で閉じるもの → 絶対で閉じるもの**」の順に潰す。
実際 C40 の根拠「追加ダメ/本体 = 0.51〜0.77」は `final_dmg`・def・ギアが共通因子として消えるため、
**A7 も敵 def も未確定のまま既に成立している**（比で閉じる型の実例）。

**宿儺に残るもの**: C43（上限超過ペナルティ）・障壁 rate/abi・宿儺 def。
⚠ ただし**運用を「≦19手」に固定すれば C43 は無期限に後回しにできる**（現行の剪定モデルのままで整合する）。

**⚠ 攻撃フェイズの仕様（ユーザー回答 2026-08-03・`gamedata/md/その他/attack_phase.md`）**:
バーストと通常攻撃は**排他**で、ゲージ100以上**かつボタンON**ならバースト・**OFFなら通常攻撃**。
シムは ①ボタンOFF（溜める）を持たず ②非バーストキャラの通常攻撃を加算しない（**C46**）。
⚠ **全員バーストするターンでは影響ゼロ**で、これまでの較正走はほぼ全ターン FB 成立＝**実害は限定的**。
ただし **FB が途切れる条件の走を作るなら、そのターンは C46 の影響下**にあることを明記して測ること。

**⚠ config の同一性担保**: 走ごとに**UI の編成保存スロット JSON（`kamipro_slots.json` の該当スロット）を
`data/<config>_slot.json` として提出する**。サブ枠・幻獣・ウェポン・ボックス補正が1ファイルに揃うため、
