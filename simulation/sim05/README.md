## 4. 設計

### 4.1 ナポレオン押し順ヒューリスティック（cands.s）

移行README のユーザー所感（実機プレイ感）を cands.s へ写す。**ただし着手前にアビ番号↔コードキーの厳密対応を確定**（下記）:

- 一次情報 napoleon.md §1.2 のマッピング: **1アビ=roy / 2アビ=pike / 3アビ=consort / 4アビ=factor**。
- ⚠**要解決の矛盾**: ユーザー所感は「**2アビ**＝強化数**10以上**か否かだけがゲート→10以上で最速」と言うが、コードの `pike`（=一次情報の2アビ）は**buffCount≥15**ゲート、`factor`（4アビ）が**≥10**ゲート。ユーザーの「2アビ」がコードの pike か factor かで設計が変わる。**G0 でユーザーに実機のアビ番号と効果を突き合わせて確定**（napoleon.md §1 が正）。
- 確定後の cands.s 方針（マッピングが一次情報どおりなら）:
  - `pike`（2アビ・旺盛/防壁・≥15で確実会心）: **buffCount がゲート付近で高スコア＝早撃ち**（会心を早く確定させ後続を底上げ）。
  - `factor`（4アビ・≥10で全体CD-1）: **buffCount≥10 で高スコア＝短縮レバーを早く回す**（他アビの使用回数を伸ばす。イフィシャント/pactcore と同じ「手数の複利」役）。
  - `roy`（1アビ・全攻撃ダメプラス tier）・`consort`（3アビ・赤ダメ ≥20で2hit）: **終盤寄せの低〜中スコア**（バフ数が乗ってから打つほど tier/hit が伸びる）。
- 実装は各 cands に `s:` を付与するのみ（エンジン本体・探索ロジックは非改修）。**golden 非影響**（ナポレオンは golden 編成に不在）。

### 4.2 アリアン回数制限×短縮の条件付き+1

ユーザー所感§2:「アリアンのアビ回数制限は、自身の短縮効果／ifishant／ナポ4アビ(factor) の CD 短縮で**上限超過発動**が可能」＝**エレインの ifishant リキャスト（`ifAlone/ifLegend/ifKnights/ifPactcore`）と同型**。

- 設計: `holy`（手動2/T）・`elegant_re`（回数ゲート）に、**短縮ソースが「クォータ消化済みのアリアンアビ」に作用したときだけ +1 枠**を付与（C21 の教訓＝「発動可能な状態のアビの回数は増やせない・CD中/クォータ消化済みのみ復活」を踏襲）。
- 短縮ソース: アリアン2アシ（光3バースト毎の自CD-1）・ナポ factor（全体CD-1）・イフィシャント系が編成にあれば同様。
- state: エレイン if枠と同型のフラット数値（`arian_holy_plus` 等）を宣言し、`guard` で参照。
- ⚠**HP参照項（A9・HP80%ゲート）は現状フルHP前提で常時発動**。厳密化は**未確定Phase(i)＝生存/現在HPモデル**以降（arianrhod.md 注記どおり保留）。

### 4.3 追撃較正（C3/C5・本丸）

- **対象成分**（arianrhod.md A1 で別枠2本確定＋エジソン系とは別）: ①アリアン バースト効果「追加ダメージ」 ②1アシ トランジェントマイト「追撃」 ③（参考）エジソン英霊武器追撃は本編成では英霊がナポなので不在＝**交絡が1つ減る**。現実装は①②とも 3倍/cap50万（アビ枠）で近似。
- **sim04 で判明済みの数値**: 追撃系は成分別 実機/sim ×2.3〜6.9・**非決定的 fit**（会心/急所RNG が乗り単発 raw を直読できない）で残差保留。
- **sim05 での解き方**: sim04/C25 と同じ「**非会心・非急所の非飽和アンカー**」原則。この編成は追撃が支配的なので、追撃単発が総ダメに効く＝アンカーが取りやすい。走の設計:
  - **モード D（全深測定・撃破まで）×5走**を基本（sim03 と同型・イベント列決定性を利用して5走で追撃成分を平均）。较正ボスの affinity/隠れ耐性がクリーンなこと（§4.4）が前提。
  - 各走で**追撃ヒットの会心/急所マーク**を記録（record_skeleton に列を用意）＝マーク一致ヒット間で raw を平均し、成分別（①②）の cap/slope を fit。
  - fit 順: **C5（追撃 cap レベル）→ C3（追撃式・合流）**。sim04 の judg/burst と同じく pre-cap raw に乖離が局在するか（深飽和一致か）をまず確認。

### 4.4 較正ボス

- **第一候補: キャスパリーグ `cath_palug` 続投**（sim04 と同じ・闇/affinity1.5・光編成に隠れ耐性非適用がゲーム内保証・max_hp=400,000,000 確定・2T討伐）。編成が変わっても**ボスのクリーンさは編成非依存**なので流用が最も安全＝環境変数を1つに絞れる。
- ただし新編成の2T討伐火力が過剰でオーバーキル切断が深すぎる場合は測定点が減る＝**より硬い/反復可能な別ボスを検討**（G2 でユーザーと確定）。max_hp 推定は sim03 と同じ T1終了HP%×ceil規約。

## 5. golden 干渉と戦略（**要ユーザー決定**）

`test/golden.mjs` は edison 編成＋configB ATK に固定され、**hecate/tetra/elaine の ATK を移行値（75558/83718/85054）へ更新すると golden が動く**（この3キャラは両編成に居るため）。取り得る戦略:

- **案A（推奨・golden は edison 固定のまま凍結）**: `DISPLAY_ATK_OVERRIDE` を**移行編成用に切り替えず**、configC は sim05 のUI/config 側で持つ。golden は sim04 の回帰基準として据え置き＝frame calib 変更時のみ再fit。sim05 の新編成検証は**別 fixture**（headless replay ケース）で担保。→ 回帰の連続性を最優先。
- **案B（golden を新編成へ移行）**: golden.mjs を napoleon 編成へ書き換え＋ATK 更新＋override 再fit（sim03→sim04 と同じ「環境が変わったら golden も移す」流儀）。ツールの主編成が名実ともに移る。→ 移行を主編成の乗り換えと位置づけるなら自然だが、回帰基準が一度死ぬ。

→ **G2 で確定**。frame calib（絶対値の土台）は編成非依存で共有されるため、**案A でも sim05 の追撃 fit 結果（DMG 定数）は golden に反映され得る**点に注意（追撃 cap 変更は edison golden の追撃成分＝低割合にも効く＝golden 値が微動しうる。意図した変動として記録）。
