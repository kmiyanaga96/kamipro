# sim01 統合分析（実装担当 = Claude Code）

設計担当の [`design_report.md`](design_report.md) の主張を検証し、実装可否・回帰影響を確定する。
入力: [`raw_data.txt`](raw_data.txt)（実機原本） / [`replay_screenshots.md`](replay_screenshots.md)（リプレイ転記）。

## 1. 入力サマリ
- 形成: 英霊エジソン ＋ ヤマト/ヘカテー/テトラ/エレイン。敵 totalHP = 84,000,000（木人）。
- 比較ルート: **A=シム推奨（Sim Opt）** vs **B=実機勘（Manual）**。両ルートともT2で撃破。

## 2. シム値の確認（ターン別・序数）
リプレイ転記の累計から（シム抽象スケール）:

| 指標 | A: Sim Opt | B: Manual | 備考 |
|---|---:|---:|---|
| T1（シム値） | **41,390,818** | 36,225,552 | A が +5,165,266（+14.3%） |
| T2（シム値） | 32,882,061 | **51,758,507** | B が +18,876,446 |
| **2T累計（シム値）** | 74,272,879 | **87,984,059** | **B が +13,711,180 上** |
| アビ手数（T1/T2） | 20 / 3（計23） | 17 / 10（計27） | A が 4 手少ない |

### 2.1 重要な事実 — シムは「2T総和が低い方」を推奨している
シム抽象スケールでは **B(Manual)の2T累計の方が大きい**（87.98M > 74.27M）。にもかかわらず
シムが推奨するのは A(Sim Opt) である。これは**バグではなく探索目的の定義による**:

- `class Sim` の探索は `cmpVec` による**ターン優先の辞書式（lexicographic）最大化**。
  すなわち「まずT1を最大化、同点ならT2、…」で順序ランクを決める。
- A は T1 を最大化（41.39M）するルート、B は T1 を犠牲（36.23M）にして T2 へリソースを後送りするルート。
- 辞書式では T1 が支配的なので、T1 で勝る **A が常に B に優先される**。2T総和は最適化対象ではない。

→ **これは「フロントロード（火力前倒し）」を是とする現行ポリシーの帰結**。固定HP木人の
ダメージレースでは、85M級ボスを早く削り切る・手数を減らす観点で前倒しが実戦的に有利
（design_report §2.3 のクリック効率 23 vs 27 手と整合）。**序数判定の符号としては問題なし**。

### 2.2 実機値（design_report §1）の扱い
design_report は実機値 A:T1=70.6M / B:T1=60.2M、2T累計はほぼ拮抗（A 82.56M ≒ B 82.55M）と記載。
これらは当方では直接再現できない実機実測のため**追認は保留**するが、シム値（上表）はスクショと一致しており、
A=T1最大・B=T2偏重という**定性的構造は実機・シムで一致**している。design_report の「Aが勝つ」結論は
実機の time-to-kill / 手数効率の観点であり、シムの辞書式ポリシーと矛盾しない。

## 3. 系統誤差の診断 — バースト追撃の減衰上限（C5）
design_report §3 の中心的主張は「**シムのバースト追撃ベース減衰上限が過小**で、実機の追撃出力
（2.6〜2.8M）を再現できない」というもの。検証する。

- 追撃は全て**アビ枠 `'abi'`（slope 0.04）**で計算（CALIBRATION_ANALYSIS §3.2 で確定済）。
- 実戦級装備のアビ上限UP合計倍率は概ね `1+U ≈ 2.40`（上限+140%）。
- 減衰式: `実ダメ = 実質上限 + (raw − 実質上限) × 0.04`、`実質上限 = ベース上限 × (1+U)`。

| 追撃 | 現行ベース上限 | 較正ベース上限 | 実質上限(×2.40) | 復元される実ダメ | 実機実測 |
|---|---:|---:|---:|---:|---:|
| ヤマト `burst_followup_cap` | 500,000 | **1,000,000** | 2.40M | ≈2.82M | 2.62M |
| ヘカテー `hecate_extra_cap` | 500,000 | **1,000,000** | 2.40M | ≈2.82M | 2.79M |
| テトラ `tetra_burst_cap` | 500,000 | **1,000,000** | 2.40M | ≈2.82M | 2.75M |
| エレイン `elaine_burst_extra_cap` | 300,000 | **800,000** | 1.92M | ≈2.28M | 2.28M |

現行(50万/30万)では実質上限が 1.20M/0.72M に留まり、減衰後でも 1.1〜1.67M 止まりで実機の 2.3〜2.8M に
届かない。較正値(100万/80万)で実機出力に整合する（design_report §3.1 の算出を追認）。

**押し順への影響（系統誤差性）**: 上限が過小だと追撃の限界価値が頭打ちになり、「追撃を積む前倒しルート」の
相対価値が**実機より低く**評価される。実戦級スケールでは A(前倒し・追撃多)の優位が縮小し、序数が反転しうる。
→ C5 は PHASE4_PLAN §2 の「cap 誤り＝系統誤差」に該当し、押し順較正として**修正対象**。

## 4. 回帰影響 — ゴールデン値の不変性（実測）
較正4値を適用した index.html のコピーで検証コマンドを実行し、**変更前後で完全一致**を確認:

| | FullBurst | TotalDmg |
|---|---|---|
| 現行 caps | 10/10 | **92,031,195** |
| C5 較正 caps | 10/10 | **92,031,195** |

ゴールデンは装備なし抽象スケール（通常≈4,000 / バースト≈30,000）で、減衰上限（数十万〜百万）に
到達しないため caps に不感。よって**較正はリファクタ品質を損なわず、実戦級スケールの精度のみ向上**する
（design_report §4 を実測で追認）。

## 5. 結論・次アクション
- **追認**: design_report の C5 較正（ヤマト/ヘカテー/テトラ=50万→100万、エレイン=30万→80万）は
  数学的・実機的に妥当で、ゴールデン値不変も実測済み。**実装を推奨**。
- **実装差分**（`index.html` の `DMG` 内）:
  - `burst_followup_cap: 500000 → 1000000`
  - `hecate_extra_cap: 500000 → 1000000`
  - `tetra_burst_cap: 500000 → 1000000`
  - `elaine_burst_extra_cap: 300000 → 800000`
  - ※スクショ由来の「50万/30万確定」コメントは実機内部仕様と乖離のため要更新（100万/80万・実機較正）。
- **テトラHELIX後 `tetra_burst_cap2`（C1, 現行100万・推定）**: 今回の較正で HELIX前が100万に揃うため、
  HELIX後(6倍/100万)との整合は別途序数で確認が必要。今回は据え置き。
- **探索ポリシーの所見（新規・C6候補）**: シムは2T総和ではなく辞書式T1優先を最適化する。固定HP木人の
  ダメージレースでは妥当だが、「2Tで撃破でき総和を重視したい」要求が出た場合は目的関数の再検討が必要。
  現方針（フロントロード是・PHASE4_PLAN §2）では問題化しないため**記録のみ**。
- **バックログ更新**: CALIBRATION_ANALYSIS.md の C5 を `open → fixed` に遷移。
- **実装結果（2026-06-26）**: `index.html` の `DMG` 4値（`burst_followup_cap`/`hecate_extra_cap`/
  `tetra_burst_cap` = 100万、`elaine_burst_extra_cap` = 80万）を較正値へ修正。検証コマンドで
  FullBurst 10/10・TotalDmg 92,031,195 を再確認（不変）。
