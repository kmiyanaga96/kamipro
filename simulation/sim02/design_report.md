- **恒常的なダメージ乖離の構造**: 
  すべてのターンにおいて、実機のダメージはシミュレータのモデル計算値に対して一貫して約 **1.7〜2.0倍** 大きくなっています（例: T1シミュ値 39.12M vs 実機値 70.63M）。これは、プレイヤーの実戦級装備のアサルト/旺盛/上限UPバフがシミュレータの想定よりも高く設定されているためです。

## 2. なぜその差が出たか（リソース推移と敗北要因）

手動順と推奨順の決定的な差は、**契晶（クリスタル）および連理魔力の蓄積効率**にあります。

### 2.1 累計契晶（cum）達成の分析
- エレインの3アシスト「契晶80以上でバースト追撃3回化」は、長期戦において極めて重要な火力ソースです。
- **シミュレータ推奨順の契晶推移**:
  - T1: `14` (チェイン5)
  - T2: `30` (チェイン5)
  - T3: `40` (チェイン5)
  - T4: `56` (チェイン5)
  - T5: `73` (チェイン5)
  - T6: `83` (チェイン5) → **T6メインフェイズ時点で80を突破し、追撃3回化が解禁**。
  - T7: `93`
- 推奨順は、T1でエレイン1アビを先行発動して契晶を消費しつつ、毎ターン5チェイン（フルバースト）を維持することで、T6時点で安全に80スタックを達成しています。これによりT6〜T7のバーストパートの火力が爆発的に向上しています。

### 2.2 連理魔力（renri）達成の分析
- テトラの連理魔力は、アビリティ12回毎またはバースト2回毎に `+1` 蓄積され、最大30でHELIX（4アビ）が解禁されます。
- **テトラ1アビ（ジャッジ）の発動回数（J）の推移**:
  - 推奨順のジャッジ発動数 J は、T1: 3回、T2: 5回、T3: 1回、T4: 2回、T5: 5回、T6: 1回、T7: 2回 と推移し、T7までに合計19回発動しています。
  - 実機ログでも、T7のテトラ1アビの2手目で「連理魔力30」に到達していることが明記されており、シミュレータの連理魔力蓄積ペースは実機の挙動と完璧に整合しています。

## 3. 乖離分析（系統誤差の特定）

T1〜T7のターン毎のログを実機（`raw_data.md`）とシミュ（`replay_screenshots.md`）で詳細に突き合わせ、系統誤差を特定します。

### 3.1 ターン毎のダメージ乖離分析

#### T1〜T4 (HP > 50% ［30%カット適用］)
- **実機通常追撃 vs 会心追撃の微小差**:
  T1の実機ログにおいて、テトラの追加ダメージは「会心」で **222万**、ヘカテーは「会心急所」で **246万** です。これは `sim01` で算出したヤマトの通常追撃（262万）やヘカテーの会心追撃（279万）と非常に近い値であり、防御値 25 のロキに対しても、減衰上限 100万 および 80万 のベース上限が適用され、会心倍率が減衰前に乗算されていることを裏付けています。

#### T5 (HP ≤ 50% ［カット解除＆被ダメ1.2倍適用］)
- **ファントムリリースによる跳ね上がり**:
  実機バーストダメージは、T4（ヤマト急所バースト 864万）から T5（ヤマト会心急所バースト 1026万、1234万）へ移行。エジソンのバーストは T4の 677万 から T5の 1310万 へと倍増しています。
  この急激な上昇は、ボスの防御ステータス自体が変化したのではなく、被ダメ倍率が `0.7` から `1.2` へ移行したこと（約1.71倍）による系統的な変化であり、モデルの移行判定タイミングも実機と完全に一致しています。

### 3.2 敵データベースの乖離
- **最大HPの乖離**: 
  `data/enemies.js` における `walpurgis_loki` の `max_hp` は `100,000,000` (1億) または `250,000,000` (2.5億) となっていますが、実機ソロ討伐時の総HPは **`980,000,000`** (9.8億) であることがログより判明しました。DOT計算や撃破判定を実機と合わせるため、`max_hp` を `980,000,000` に修正する必要があります。
- **属性相性の確認**: 
  光→幻の属性相性は等倍（affinity = 1.0）であることが有志データより確定し、`data/enemies.js` の `affinity: 1.0` への修正が正しいことを確認しました。

## 4. 影響度検証（回帰）

### 4.1 既存テストへの影響
- 今回特定した `walpurgis_loki` の `max_hp` (2.5億 -> 9.8億) および `affinity` (1.5 -> 1.0) の変更は、いずれも `index.html` に記述されている敵DBオブジェクト `ENEMY_REGISTRY.walpurgis_loki` の内部値のみを対象としています。
