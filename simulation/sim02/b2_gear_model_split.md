## 0. naB の構造（レバー分解）

`src/sim.js _na()` より、単発通常攻撃ダメ（raw・減衰前）は乗算枠の積：

```
naB_raw = gk × (1+aslt) × elemBox × (1+vigor) × (1+crit) × (1+acute) × (1+spec)
gk      = dispAtk × (1+dmgup) × (1+other) × misc / enemy_def      … GEAR_K_C[owner]
elemBox = affinity(1.5) + elem枠
```
表示（＝実機で読める値）は `_naForAbi()` で **減衰cap**（`decay_na.cap1=350,000×(1+na_cap)`）を通した後。

∴ naB を動かすレバーは分離可能で、**「gear/context 由来」と「model 由来」に二分できる**：

| レバー | 種別 | naBへの効き | 現在の確度 |
|---|---|---|---|
| **enemy_def** | context | ∝ 1/def・**全キャラ共有スカラ** | **暫定（=10）** ★最不確実 |
| **dispAtk**（per-char） | gear | ∝ dispAtk | 育成途中スクショ実測・**試行1一致は未確認** |
| **na_cap**（表示上限） | gear | 表示naBの天井を規定 | 「各cap等」で B1 は未再現 |
| assault/vigor/elem/spec/crit/acute/dmgup/other | gear | 乗算スタック | 試行2キャッシュ流用・試行1一致未確認 |
| affinity | context | elemBox 加算 | **確定 1.5** |
| _na() の枠構造・係数 | **model** | 上式そのもの | 検証対象 |

**含意**: baseline の約2×は、model（_na 構造）に触れる前に**3つの gear/context スカラ（def・dispAtk・na_cap）が全て未確定**。
このうち **enemy_def は「全キャラ一律に効く共有スカラ」**で、B1-stage2 が観測した
「edison/yamato/hecate/elaine が一律×1.19〜1.20」＝**共有乗算スカラの署名**と整合する。

## 1. 机上で判明したこと（プローブ実測・`scratchpad/nab_probe2.mjs`）

試行2キャッシュ GEAR（assault2.826/vigor0.6876/burst_dmg4.86）＋ DISPLAY_ATK_OVERRIDE ＋ def10 で
`_na()` を各キャラ所有者視点で評価：

### (a) T1 コールド naB（バフ未蓄積・戦闘開始直後）
| char | rawNaB(def10) | rawNaB(def20) |
|---|---|---|
| edison | 83,424 | 41,712 |
| yamato | 67,117 | 33,558 |
| hecate | 63,097 | 31,549 |
| tetra | 69,713 | 34,857 |
| elaine | 67,690 | 33,845 |

→ **def を 10→20 にするだけで全 naB が正確に半減**（naB∝1/def を数値確認）。**def は 2× baseline の単独説明変数たりうる。**

### (b) ターン内蓄積は十分モデル化されている（B1 の F1 はターン跨ぎに局在）
- シム tetra: **コールド 69,713 → 攻撃フェイズ 360,264（B1-stage2 計装値）＝×5.2**。
- ∴ シムは**ターン内**のバフ蓄積は大きく効かせている。B1 の「naB 成長×1.2」は**ターン跨ぎ（T1→T4 の同フェイズ点比較）**に限定した現象であり、
  「シムがバフ蓄積を過小」は**ターン開始状態の持ち越しに局在**（毎ターン頭でスタックが実機ほど残っていない／伸びていない）。

### (c) B1 の baseline 比較は cap 状態が非対称
- B1 の「sim tetra naB T1=36万 vs 実機 de-cut 77万＝47%」は、**36万＝raw未cap**・**77万＝表示cap後**の混在比較。
- 実機の表示単発通常が **de-cut 771,429**（54万/0.7）に達する事実は、`decay_na.cap1=350,000` を大きく超える
  ＝**実機 build の na_cap（通常ダメ上限UP）が相当大きい**ことを含意（B1 未再現枠）。
- ∴ **baseline 2× の「絶対量」自体が現データでは不確実**。切り分けには cap を揃えた同状態比較が必須。

## 2. 実機取得手順（切り分けを決定的にする・優先度順）

> 目的：**gear を完全に pin して replay 比較の残差スカラを def or model に一意化する**。
> B1 の replay 比較（`_execKeyNoGuard` 強制再生）は手法として正しく、欠けているのは**試行1の実装備**のみ。

### ★A（必須・最優先）: 試行1の**実装備フルスナップショット**
これが揃えば dispAtk・全 gear box・na_cap が unknown から外れ、残差＝def or model に一意化する。
1. **各キャラの表示攻撃力**（編成画面の数値・edison/yamato/hecate/tetra/elaine 各1つ）。
2. **装備スキル全枠の％**：アサルト／旺盛／属性値／特殊攻撃／急所／会心発動率／与ダメージ／その他、
   **＋上限UP3枠（通常na_cap・アビabi_cap・バーストburst_cap）**。← na_cap を必ず含める。
3. **幻獣構成**（メイン1／サブ5／サポート1）と**加護 weapon_amp**。
4. **英霊ランク**・各キャラの**Lv／上限解放**（85/90 で ATK 補正が変わる）。

### B（def を単独分離する clean アンカー）
- **単発通常攻撃**を、**会心・急所の有無を明記**して記録（できれば非会心・非急所の hit）。
- **その通常が発生した押下位置**（直前までに押したアビ）を記録＝replay で同一バフ状態を再現できる。
- **cap 張り付き判定**：同一キャラの通常が同ターンで**同じ値に頭打ち**なら cap 到達＝na_cap 較正が必要。
- A で gear を pin ＋ この通常を同状態 replay で突き合わせ、**残差スカラ＝def**（affinity=1.5 確定のため）。
  複数キャラで取れれば「**単一 def が全キャラを同時整合させるか**」で def（共有）か per-char model かを判定。

### C（ターン跨ぎ成長＝F1 の本丸を測る）
- **同一キャラ・同一 crit/急所状態・同一ボスフェーズ（×0.7）**の単発通常を **T1 と T4 で各1つ**記録
  → 実機のターン跨ぎ naB 成長倍率（cap 考慮の clean 値）を sim ×1.2 と直接比較。
- 各ターン頭（攻撃フェイズ後）の**バフ実stack数**（assault/vigor/puvoir光攻UP/legend の各カウント）を記録
  → sim replay の stack 数と照合し、**どの枠が持ち越し／成長で実機に届かないか**を局在化。

### D（フェーズ倍率・共通メタ）
- 各ターン末の**ボスHP%**（×0.7 / ×1.2 境界の確定）。C22 用に各ターン頭の**契晶ストック/累計**も継続記録。

> **収集の最小セット**＝ A（必須）＋ B の非会心通常1つ×2キャラ。これだけで baseline の def-or-model が決まる。
> C は F1 成長の局在用（余力があれば）。

## 3. 暫定の切り分け判定（机上・§2 取得で確定）

- **baseline（約2×）**: **gear/context 由来の公算が高い**（def=暫定・dispAtk/na_cap 未 pin・共有スカラ署名）。
  ただし _na model を否定はできない＝§2-A+B で決着。**最有力単独仮説＝enemy_def 過小**（10→実効20級）。
- **成長（×1.2 vs 実機×1.7）**: **model 由来の公算が高い**（cap-robust な B1 最強所見）。
  ターン跨ぎで**共有乗算枠（全体assault/vigor/elem 等）の持ち越し・累積がシムで実機に届かない**のが本命。§2-C で枠を局在化。
- ∴ **kill-turn ゲート（KILL_TURN_DESIGN.md §7.4）への供給**：絶対精度は「def 確定（baseline）＋持ち越し枠較正（成長）」の
  2段が前提。**単一フェーズ倍率補正では撃破ターン精度は出ない**（B1 の結論を裏付け）＝S1+S2 は naB 較正後。
