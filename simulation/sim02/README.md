# sim02 — テトラHELIX後追撃の減衰上限の確定（C1）

- **主題**: C1（CALIBRATION_ANALYSIS.md）。テトラ4アビ(HELIX)発動後のバースト追撃のベース減衰上限を確定する。
- **状態**: **準備完了・Antigravity査読待ち**（データ収集前）。査読通過後にユーザーが `raw_data.txt` を実測記入 → 分析・実装。

## 準備ステップ記録（C1測定設計・Antigravity査読対象）
> sim02 はデータ収集に入る前に、**測定設計そのものを Antigravity が査読**する運用とする（誤った測定設計での実機計測の手戻りを防ぐ）。
> 本節と `raw_data.txt`／下記「進め方」が査読対象。査読結果は `design_report.md` に記録する。

**準備で確定した設計判断（Claude Code・コード根拠つき）:**
1. **測定範囲を1ターンに圧縮**: C1 は HELIX後追撃の1値から減衰式で逆算可能。7T全分解は不要（前段は連理魔力到達の確認のみ）。→ トークン・整理ミスを構造的に削減。
2. **逆算式**（コード `tetra.onBurst` = `_decay('abi', _na()×6, cap)` 準拠）: `実ダメ = ベース上限×(1+U) + (naB×6.0 − ベース上限×(1+U))×0.04`。
3. **残存バフの2系統分離**（下記「残存バフの扱い」）: ①倍率系は naB 実測で自動計上＝列挙不要 / ②アビ上限UP系のみ総アビ上限UP(U)へ合算必須。
4. **会心の段差回避**: naB・追撃は同一バフ状態・できれば会心なしで採取。

**Antigravity への査読観点（チェックしてほしい点）:**

## 進め方（トークン・ハルシネーション・整理ミス回避の設計）
7ターン全分解はしない。C1 は「HELIX後追撃の1値」から減衰式で cap を逆算できる:
- **測定対象は HELIX後バーストの1ターン分のみ**。T1〜前段は「連理魔力がHELIX閾値(30)に到達したか」の前提確認だけ。
- 逆算: `実ダメ = ベース上限×(1+U) + (naB×6.0 − ベース上限×(1+U)) × 0.04`。既知（実ダメ・naB・U=総アビ上限UP）から未知（ベース上限）を解く。
- **転記と計算を分離**: 実機値は `raw_data.txt`/`replay_screenshots.md` に逐語、算術は `integrated_analysis.md` で式を明示。

### 残存バフの扱い（2系統で正反対・要注意）
T6/T7 のバフは多数残るが、コード（`tetra.onBurst` ＝ `_decay('abi', _na()×6, cap)`）上で扱いが割れる:
- **① 倍率系（攻撃力/アサルト/属性/旺盛/会心/急所/特殊攻撃）** … `_na()` に内包。**測定ターンで naB を実測すれば自動で入る**＝個別列挙不要。
- **② アビ上限UP系** … `_decay` の `(1+GEAR.abi_cap)` に効くが naB に入らない。**naB 実測では拾えない**ため、`raw_data.txt` #1 の「総アビ上限UP」に装備＋残存バフを合算必須。
  現行シムは上限UPを装備でしか持たないため、バフ由来があれば較正ギャップ候補として分析で扱う。
- **会心**: 段で式が変わるため naB と追撃は同一バフ状態・できれば両方「会心なし」で採る。
