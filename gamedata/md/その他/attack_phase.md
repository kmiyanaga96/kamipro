# 攻撃フェイズの仕様（一次情報）

> **種別**: 一次情報（ユーザー提供・実機仕様の直接申告）
> **出所**: ユーザー回答 ／ **受領日**: 2026-08-03 ／ **原文ママ**（本文は書き換えない。訂正は冒頭注記で行う＝damage_frames.md 方式）
> **経緯**: M1（過去 sim の全成分突合）で「シムが毎ターンの通常攻撃を一切加算していない」「反撃が未モデル化」と
> 判明したため、Claude Code から仕様を照会した回答。
> 関連: CALIBRATION_ANALYSIS **C24（ゲージ乖離）/ C45（反撃）/ C46（通常攻撃・攻撃フェイズの排他）**

## 1. 原文（ユーザー回答 2026-08-03）

> 1. 反撃メカニズムは有志検証データが存在しない。地道に統計的較正をする必要がある。
> 2. 攻撃フェイズで、通常攻撃とバーストを同時に行うことはできない。バーストゲージが100以上のキャラは、
>    「バースト発動」ボタンがONになっていればバースト攻撃をする。100以上でも、ボタンがOFFならば通常攻撃。

### 追加回答（同日・Claude Code の再質問への回答）

> 1. 反撃は、自身が攻撃されたときに発動して敵にダメージを与える効果。反撃とは全く別に、ムーンコードの効果として
>    回避率（ほぼ）100%があるため、攻撃されるとダメージはないが反撃する、という事象が発生している
>    （今までのtrialはすべてこのケース）。
> 2. ゲージは1ヒット+10は「ゲームの仕様」であり、これが変化するのは「バーストゲージ上昇量UP」バフや、
>    何らかの敵のデバフなど。

## 2. 仕様として確定した点

| # | 仕様 |
|---|---|
| 1 | **攻撃フェイズで各キャラが行うのは「バースト」か「通常攻撃」のどちらか一方**（同時には行わない） |
| 2 | バーストする条件は **ゲージ100以上 かつ 「バースト発動」ボタンON** |
| 3 | **ゲージ100以上でもボタンOFFなら通常攻撃**＝「溜める」はプレイヤーの選択肢として実在する |
| 4 | **反撃は「自身が攻撃されたとき」に発動**して敵にダメージを与える |
| 5 | **ムーンコード（ヘカテー2アシ）中は回避率ほぼ100%**＝**被ダメージ0でも「攻撃された」ので反撃は発動する**。**これまでの trial はすべてこのケース**（味方被ダメ0なのに反撃が出ていた理由） |
| 6 | **バーストゲージは「1ヒット +10」がゲームの仕様**。変化するのは「バーストゲージ上昇量UP」バフや敵のデバフなど |
| 7 | **反撃の機構（誰がいつ何回反撃するか）には有志検証データが存在しない**＝統計的較正で推定するしかない。⚠ ただし**ヘカテーのムーンコード反撃そのものは一次情報がある**（§5） |

## 3. 現行シムとの差（2026-08-03 時点・`src/sim.js` `_attackPhase`）

```js
for(const c of CHARS){ if(this.g[c]>=FB_THR){ this.g[c]-=100; ...this.burst(c,...); atk.push(c); } }
```

| 実機 | シム | 差 |
|---|---|---|
| ゲージ100以上＋ボタンON → バースト | ゲージ100以上 → **必ず**バースト | **ボタンOFF（溜める）という選択肢が無い** |
| それ以外 → **通常攻撃** | それ以外 → **何もしない** | **非バーストキャラの通常攻撃が未モデル化** |
| 反撃あり | 反撃なし | **未モデル化** |

### ⚠ 影響範囲は限定的（データで確認済み・2026-08-03）

**「全員がバーストするターン」では、上の差は定義上ゼロになる**（バーストと通常攻撃は排他だから）。
これまでの較正走はいずれも**ほぼ全ターンで5人ともバースト**していた:

| 走 | FB 成立 |
|---|---|
| `test/golden.mjs` 3 fixture | **10/10 ターン**（edison/raw・edison/cal・napoleon/static とも） |
| sim05 pre-trial（両面宿儺） | T1・T2・T3 すべて true |
| sim03 D走 T1/T2（5 trial） | 各ターン5人バースト（`攻撃フェイズ` 行は本体+追加ダメのみで通常攻撃行が無い） |

∴ **通常攻撃の未モデル化が効くのは「FB が成立しないターン」だけ**。
唯一まともに効いているのが **sim04 の M1 無アビ素走**（アビ0手＝T1/T3 が通常攻撃のみ）で、
あの走は元々 `calib_na` の測定用である。

⚠ **ただし「効かない」ことと「モデルとして正しい」ことは別**。上限超過ペナルティ（C43）や
新しい敵・編成で FB が途切れる条件が出れば、この欠落は即座に binding する。

## 4. ゲージ生成 ── 仕様は「1ヒット +10」（2026-08-03 確定）

**ユーザー回答により確定**: バーストゲージは **1ヒット +10** がゲームの仕様。変わるのは
「バーストゲージ上昇量UP」バフや敵のデバフ。

### 4.1 ⚠ Claude Code の誤りの訂正

初版で「**『1ヒット=+10』仮説は反証される**」と書いたのは**誤り**だった。根拠にしたのは
「T3 のゲージ増分が3本とも同一なのに通常攻撃のヒット数が trial 間で違う」ことだが、
**実際は転記側にヒットの取りこぼしがあった**:

| trial | T3 の記録ヒット数（エジソン/ヤマト/ヘカテー/テトラ/エレイン） | T3 ゲージ増分 | 判定 |
|---|---|---|---|
| 01 | **3 / 1 / 1 / 3 / 1** | +30 / +10 / +10 / +30 / +10 | **完全一致** |
| 02 | **1** / 1 / 1 / 3 / 1 | +30 / +10 / +10 / +30 / +10 | エジソンの記録が2ヒット足りない |
| 03 | 3 / 1 / 1 / **1** / 1 | +30 / +10 / +10 / +30 / +10 | テトラの記録が2ヒット足りない |

**trial01 は仕様と完全に一致する**。trial02/03 は同じキャラ構成（エジソンとテトラだけ3段攻撃）なのに
記録だけが欠けており、**転記漏れ**（またはゲージ欄の使い回し）と考えるのが自然。
∴ **ゲージ増分は通常攻撃ヒット数の検算に使える**（記録品質のチェックサム）。

### 4.2 現行シムとの差

- **シムは通常攻撃由来のゲージ生成を持たない**（アビリティ由来の `partyBG`・cascade・betaia・factor 等のみ）。
  ∴ **1ヒット+10 は未実装**＝C24 の系統乖離の一因。
- ⚠ ただし C46 と同じく**影響範囲は限定的**: これまでの較正走は**ほぼ全ターン FB 成立**しており、
  ゲージが足りずにバーストを逃す場面が出ていない。**FB が途切れる条件で初めて binding する**。

### 4.3 未解明（記録しておく）

**T1 だけ全員が 0 → 100 に達している**（3ヒット＝+30 のはずなのに）。3 trial とも同じ。
∴ **T1 には通常攻撃以外のゲージ源がある**（戦闘開始時の付与／敵の開幕行動「ハジマルニャン」／幻獣効果 等）。
**本記録からは特定できない**ので、C24 の材料として保全する。

## 5. 反撃 ── ダメージ式の一次情報は既に `hecate.md` §1 にあった

⚠ **Claude Code の調査不足の訂正**: C45 起票時に「反撃は有志検証データが存在しない」と書いたが、
**ヘカテーのムーンコード反撃については一次情報が既にリポジトリにあった**
（`gamedata/md/神姫/hecate.md` §1.2 アシスト2 メイビームーンズ）:

> **テキスト原文**: …ムーンコード発動の間、回避率UP・会心・旺盛・注目効果・**攻撃を回避したとき10倍光**（ダメージ）
> **有志検証データ**: …**ダメージの減衰は150万**。回避率はかなり高い。**限定行動なども回避して反撃できる**。

しかも **`hecate.md` §2 に「※回避率UP・反撃（10倍/減衰150万）・注目効果は現状シム未モデル化」と既に明記されていた**。

### 5.1 検算（桁は合う）

一次情報の「10倍 / 減衰150万 / アビ枠」で pre-trial T3 の反撃を見積もると:

| | 値 |
|---|---|
| シム T3 終了時の hecate `_na` | 1,959,112 |
| raw = `_na` × 10 | 19,591,116 |
| 実効cap = 150万 ×(1 + GEAR.abi_cap + パーティ上限UP) | 3,600,000 |
| 減衰後（アビ枠・slope 0.04） | **4,239,645** |
| **実機（pre-trial T3・2発）** | **3,882,584 / 3,886,384**（平均 3,884,484） |
| 実機/シム見積り | **×0.916** |

⚠ 減衰枠（アビ枠と仮定）・`_naOwner`・T3 のバフ状態はいずれも仮定＝**桁の検算にすぎない**。
それでも **ダメージ側は一次情報でほぼ説明できる**と言える。

### 5.2 ∴ C45 の本当のブロッカーは「トリガー」

**残っているのは「いつ・何回 攻撃されるか」**＝**敵の行動モデル**であり、シムはこれを一切持たない
（ROADMAP の未確定Phase「敵行動」）。ユーザーの言う「有志検証データが無く統計的較正が要る」は
**ここ**を指すと解釈するのが整合的。

- pre-trial T3: 反撃 **2発**（敵行動は「ヘカテーに通常攻撃」）
- sim03 D走 T1/T2: 5 trial 合計 21,751,141
- sim04 trial01 T2: ヘカテー 2,877,682（1発）

⚠ 「敵1回の攻撃で反撃何発か」は上記だけでは決まらない（多段攻撃なら1ヒットごとに反撃する可能性）。
→ ★**2026-08-07 のユーザー回答で決着（§6）**＝**1ヒットにつき1反撃**。上の「可能性」が正しかった。

## 6. 反撃の発動回数 ── **敵の1攻撃につき1反撃**（ユーザー回答 2026-08-07・原文ママ）

> 反撃はgamedataが基礎ダメージデータで、敵1回の攻撃に対し反撃1回。
> すなわち、敵が通常三段攻撃した場合は3回反撃する。

### 6.1 仕様として確定した点

1. **ダメージ式の一次情報は `gamedata/md/神姫/hecate.md` §1.2 が正**（10倍光・減衰150万）＝§5.1 の検算の前提が追認された。
2. **反撃回数 = 敵の攻撃ヒット数**（1ヒット1反撃）。**三段攻撃なら3反撃**。
   ＝「敵の攻撃1回」は**アクション単位ではなくヒット単位**で数える。

### 6.2 既存データによる検証（★ユーザー許可 2026-08-07「今までの sim で敵行動に対し攻撃回数・反撃回数とも記録してあるから、必要に応じてデータ参照してよい」）

sim03 / sim04 / sim05 の全 trial から「敵の行動」と「反撃の発数」の対を機械抽出した（読み取り専用・再現＝下記）。
**規則と矛盾する行は1件も無い**:

| trial | T | 敵の行動（記録どおり） | 対象 | 記録上の段数 | 反撃 発数 | 整合 |
|---|---|---|---|---|---|---|
| sim04 trial01 | T2 | ヘカテーに通常攻撃 | ヘカテー | 1 | **1** | ✅ |
| sim04 trial02 | T2 | ヘカテーに**通常二段攻撃** | ヘカテー | **2** | **2** | ✅ |
| sim04 trial03 | T2 | ヘカテーに通常攻撃 | ヘカテー | 1 | **1** | ✅ |
| sim04 trial11 | T2 | ヘカテーに通常攻撃 | ヘカテー | 1 | **1** | ✅ |
| sim04 trial12 | T2 | ヘカテーに通常攻撃 | ヘカテー | 1 | **1** | ✅ |
| sim04 trial13 | T2 | ヘカテーに通常攻撃 | ヘカテー | 1 | **1** | ✅ |
| sim05 pre-trial | T2 | **テトラ**に通常攻撃 | 他キャラ | 1 | **0** | ✅ 非対象＝反撃なし |
| sim05 pre-trial | T3 | ヘカテーに通常攻撃 | ヘカテー | （1と読める） | **2** | ★下記 |
| sim03 trial01〜05 | T1 | ハジマルニャン | 技名のみ＝不明 | ? | **0** | —（対象が読めない） |
| sim03 trial01〜05 | T2 | ドウシタラニャン | 技名のみ＝不明 | ? | **1** | —（対象・段数とも読めない） |

**★ここから分かった2点**:

1. **`trial02` の「通常二段攻撃 → 反撃2発」が規則の直接証拠**（段数が明示された唯一の行で、発数と一致する）。
2. **⚠ 行動名の表記は段数の記録として信用できない**。pre-trial T3 は「ヘカテーに**通常攻撃**」としか書かれていないのに
   **反撃が2発**＝**実際は2ヒットだったが段数が書き落とされている**。
   ⭐ **味方側も同じ**（テトラの judg ph2 が pre-trial で T1=3ヒット / T2=1ヒット / T3=3ヒット と揺れる＝三段攻撃は確率）。
   ∴ **敵の攻撃も毎回 段数が揺れる**と考えるべきで、**「通常攻撃」という記録から1ヒットと決めてはいけない**。

∴ **反撃の発数はそのまま「直前に敵が何ヒット当ててきたか」の観測値**になる（むしろ**行動名より信頼できる**）。
⭐ **M7 の記録価値が上がった**＝反撃の発数を記録すれば、**敵の行動モデル（C45 の真のブロッカー）の入力データが同時に取れる**。

**⏳ このデータで まだ埋まらないもの**（＝敵の行動モデルの本体）:
- **誰を狙うか**（ヘカテー以外を狙った回はそもそも反撃が出ない＝ヒット数を観測できない）
- **各ターンに何回行動するか**・**段数の分布**（現データは対象がヘカテーの回が **7件**しかなく、うち段数が確定するのは 2件）
- 技名だけの行動（`ハジマルニャン` / `ドウシタラニャン`）の攻撃性（sim03 の T2 は反撃が出ている＝**攻撃を含む**）

### 6.3 C45 への影響（**ブロッカーの範囲が狭まった**）

- ✅ **ダメージ式**（§5.1）と ✅ **多重度**（本節）が揃った。
- ⏳ **残るのは「いつ・誰に・何ヒット攻撃してくるか」だけ**＝敵の行動モデル（ROADMAP 未確定Phase「敵行動」）。
- ⚠ **ムーンコード中は回避率ほぼ100%＝被ダメ0でも反撃する**（§1 追加回答）ので、
  **「味方の被ダメージ」からは敵のヒット数を復元できない**＝**反撃の発数そのものを数えるのが唯一の観測経路**。
- ⚠ **通常攻撃の三段攻撃は C48（judg ph2 が1ヒット）・C24（ゲージ1ヒット+10）と同じ「ヒット多重度」の話**＝
  **敵側にも味方側にも同じ構造がある**。設計は3件まとめて行う。
