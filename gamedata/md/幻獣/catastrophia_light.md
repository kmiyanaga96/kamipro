## 2. シムデータ (Claude Code編集可) ##

### §2.1 各データのシム内呼称 ###

- **registry キー**: `catas`（`gamedata/js/summons.js` の `SUMMON_REGISTRY`）。
  ⚠ **正式名は「光天獄カタストロフィア」だがキーは `catas` のまま据え置く**（保存済み編成スロットが参照しているため）
- **ピュアイノセント①（スキル効果量50%UP）**: `mainEffect.weapon_amp = 0.50` — `applyGear` の `weaponAmp` に加算され、
  **全ウェポンスキルと手動追加補正の pct に `×(1+weaponAmp)`** として掛かる（メイン枠・サポート枠のみ発動）。
  ⚠ **一次情報は `[レイ][シャイン][ルミナ][セイクリッド]` に限定しているのにシムは無差別に掛けている**＝**C50**（§2.4）
- **ピュアイノセント②（光属性キャラの攻撃100%UP）**: `mainEffect.box.assault = 1.0` — `GEAR.assault` へ
  **素の fraction で加算**（weapon_amp 倍率は掛からない）。
  枠の根拠＝`gamedata/md/その他/damage_frames.md` ①攻撃枠「幻獣効果の『X属性キャラの攻撃UP』はこの枠」
- **神光の抱擁（サブ幻獣効果・光属性攻撃30%UP）**: `subEffect.box.elem = 0.30`（**2026-08-07 に §1 受領を受けて新規配線**）。
  枠の根拠＝同 ②属性枠「幻獣効果の『X属性攻撃UP』がこの枠」。**無条件**（ラジエルと違い `condition` を持たない）。
  ⚠ **configC はカタスをメイン＋サポートに置いている＝サブ枠ではない**ので、configC の GEAR は**この配線では動かない**
- **召喚攻撃（イマキュレートレーザー）**: **未モデル化**（呼称なし・Phase 6 `onSummon` 待ち）

### §2.2 シム判明データ ###

- `atk: 4500` / `hp: 900`（Lv150・**2026-08-07 に §1.1 受領を受けて placeholder の 0/0 から修正**）。
  ⚠ **ダメージ計算には使われない**（表示攻撃力への幻獣寄与はUIの手動合計入力 `summonAtkTotal`）＝
  **この修正で数値は1円も動かない**。カタスを ATK 目的で採用するなら UI の幻獣ATK合計に手で含めること。
- **メイン枠・サポート枠の両方で `mainEffect` が発動する**（`applyGear`: `SUMMON_ROLES[i]!=='sub'` が main/support の判定）。
  ∴ **メイン＋サポート＝カタス2体**なら `weaponAmp = 1.0`・`GEAR.assault += 2.0`。
  ⚠ **サポート（フレンド）枠で加護が全量乗るか**は**実機で未確認のまま**（シムの前提）。外れると**全成分が一律 ×0.83**（§2.3 H1）。
- **未モデル化**: 召喚攻撃「イマキュレートレーザー」（光属性ダメージ特大＋**光属性キャラのダメージ上限UP**・10T[初回0T]/2T・
  **係数1:100（サポート幻獣なら80）／固定値25万／係数2:25／ヒット数11**）。Phase 6（`onSummon`）待ちでシムは召喚を発動しない。
  ⚠ **ダメージだけでなく「ダメージ上限UP」も落としている**＝実装時は cap 枠（`_partyCapUp` 系）への加算も要る。
  ⚠ **実装した際は本節を必ず更新すること**（CLAUDE.md §1 の規律）。

### §2.3 ★configC（sim05）が カタス×2 であることの検算（2026-08-07） ###

**ユーザー申告**（2026-08-07）＝「sim05 はメイン・サポート幻獣ともにカタス」。
リポジトリには幻獣枠の記録が無かった（`_configSig` は**幻獣キーを持たず、畳んだ結果の GEAR しか持たない**）ため、
**台帳 `simulation/sim05/data/configC_cache_20260803.json` の GEAR を逆算して申告と一致するかを検証した**。

`configC_gear_panel.md` §2.0 の proper v1 → proper v2 の枠別比:

| 枠 | v1 | v2 | 比 |
|---|---|---|---|
| vigor / acute / crit_rate / na_dmg / abi_dmg / burst_dmg / na_cap / abi_cap / burst_cap | — | — | **全枠が厳密に ×1.111111…（=10/9）** |
| **assault** | 3.204 | **5.56** | ×1.735（★1枠だけ外れる） |
| elem | 1.04 | 1.1 | ×1.058（パネル外の別入力＝武器/入力側が動いた） |

- **9枠が一律 ×10/9** ＝ 武器個別の強化では起こりえない。`(1+weaponAmp)` が **1.8 → 2.0** になったときだけ全枠一律に効く
  ＝**加護の合計が 0.8 → 1.0**（旧＝守護 0.40×2 に相当 → 新＝**カタス 0.50×2**）。
- **assault の残差**: `3.204 × 10/9 = 3.56` に対し実際は **5.56** ＝ **差 +2.00**。
  これは `box.assault` からしか来ない量で、**カタス 1.0 × 2体 = 2.00 に厳密一致**する。

⇒ **台帳 GEAR（proper v2）は カタス メイン＋サポートを既に含んでいる**（再現＝`node tools/calib_replay_compare.mjs` の E2 が bit 一致）。

**寄与の実測**（台帳条件・記録ルート10Tの強制リプレイ・押し順固定）:

| 条件 | GEAR.assault | 10T 総ダメージ | 台帳比 |
|---|---|---|---|
| **H0 台帳（カタス メイン+サポート）** | 5.560 | **2,823,338,240** | ×1.0000 |
| H1 カタス1体ぶんだけ（サポート加護が乗らない場合） | 3.670 | 2,349,591,151 | **×0.8322** |
| H2 カタス無し・加護0.8（旧 v1 条件＝守護×2 相当・⚠当時の幻獣枠も未記録） | 3.204 | 2,439,374,393 | ×0.8640 |
| H3 幻獣なし（加護0・box0） | 1.780 | 1,857,704,033 | ×0.6580 |

⚠ **∴ カタス×2 は総ダメージの ×1.52 を担っている**（H3→H0）。**既に入っている**が、
**「サポート枠でも加護が全量乗る」というシムの前提が外れると全成分が一律 ×0.83 になる**（H1）＝
**この1点は実機で未確認のまま**（§2.2 の ⚠ と同じ項目）。

⚠ **ただし C25/C40/C44 の説明にはならない**: `assault` は ATK 項＝**全成分の cap 前 raw を一律に動かす**ので、
「バースト本体は過大・他成分は過小」という**符号が成分ごとに逆の乖離は作れない**。
しかも H1 方向（下げる）は、既に過小な成分をさらに過小にする。

### §2.4 ★C50 — 加護の適用範囲（**§1.2 受領で「疑い」から「確定した限定」へ変わった**・2026-08-07） ###

**受領した原文**（§1.2）＝「装備中のスキル**[レイ][シャイン][ルミナ][セイクリッド]**の効果量50%UP／光属性キャラの攻撃100%UP」。
∴ **加護は4つのスキル名に限定されている**（ハギトの「ルミナ/シャイン/レイ/セイクリッド の効果量40%UP」と**同一の4名**）。

**シムの実装**は `applyGear` の `GEAR[sk.box] += (sk.pct/100)*(1+weaponAmp)` ＝
**装備中の全ウェポンスキルに無差別**に掛ける（`gamedata/js/weapons.js` の全 `skills[]`）。

**⚠ まだ決められない**: `WEAPON_MASTER` はスキルを**効果種別名**（アサルト／エクシード／エラボレイト／テクニカ／
クリティカ／スティンガー／ヴィゴラス／ディフェンダー）で持っており、**[レイ][シャイン][ルミナ][セイクリッド] という
呼称はリポジトリのどこにも存在しない**。∴ **4名がどの効果種別に対応するのか**が分からないと修正できない。
- **仮説A（無害）**: 4名は**光属性ウェポンスキルの総称**＝実質すべてに乗る → **現行実装で正しく C50 は closed**。
  ⭐**ハギト（守護天使シリーズ）とカタス（カタスシリーズ）が別系統なのに完全に同じ4名を挙げている**のは、
  この4名が「光属性の標準スキル名セット」であることを示唆する（**弱い状況証拠**であって確証ではない）。
- **仮説B（有害）**: 4名は10種近くある効果種別のうち**4つだけ**＝**残りの枠はシムが2倍持っている**。

**振れ幅の実測**（台帳条件・記録ルート10T・押し順固定。加護が「どの枠に乗るか」だけを変えた）:

| 条件 | 10T 総ダメージ | S0 比 |
|---|---|---|
| **S0 全枠に乗る（★現行シム）** | **2,823,338,240** | ×1.0000 |
| S1 どの枠にも乗らない（＝攻撃UP+100% のみ有効） | 2,087,634,872 | **×0.7394** |
| S2 攻撃系（assault/elem/vigor）のみ | 2,356,614,502 | ×0.8347 |
| S3 ダメージUP系（na/abi/burst_dmg）のみ | 2,111,421,257 | ×0.7478 |
| S4 上限UP系（na/abi/burst_cap）のみ | 2,421,074,183 | ×0.8575 |
| S5 確率系（acute/crit_rate）のみ | 2,136,749,701 | ×0.7568 |

⇒ **C50 の最大振れ幅は −26%**（S0→S1）。**仮説B が正しければシムはさらに過小になる**
（現状でも実機に対し T1 で 6割しか出ていない＝`simulation/sim05/analysis/integrated_analysis.md`）。
∴ **C50 は「シムを下げる」修正**であり、**下げた分は C40/C41 側がもっと大きく不足していることを意味する**。

**⏳ 決着に必要なもの（ユーザー依頼）**: **実機のウェポン詳細に表示されるスキル名**。
configC の10本のうち数本でよい＝例えば `directorel`（六欲天デレクターレ）のスキル名が
「〜のルミナ」「〜のエクシード」…のどちらの体系で表示されるかが分かれば、仮説A / B は1回で決まる。
