### ★ M3 の設計 ── **バフ別 ablation 梯子**（ユーザー確定 2026-08-06）

> **ユーザー指示**: 「**バフ0本 → 特定のバフ1本 → 特定のバフ2本 …** を、**各バフに対して**最大限行う」。
> ＝**one-at-a-time の ablation 梯子を、バフごとに**張る。討伐不要なのでダメージだけを大量に測る。
> ✅ **この設計なら C40 の関数形は決まる**（下の「なぜ contrast が要るか」を満たしている）。
> ⚠ Claude Code は当初これを「全部盛り1点」と読み違えて反論した＝**誤読。設計はユーザー案で正しい**。

**なぜ contrast（対照）が要るか**（設計の根拠・残す）: 追加ダメも本体も**同じバフ量の関数**なので、
**全部盛りの1点**では `追加 = f(本体)` と `追加 = g(バフ量)` が区別できない（共線）。
**trial01 がまさにこれで止まった**＝12点あって r=0.688・回帰 `追加 = 0.302×本体 + 5.38M` の切片が平均の 54% を占めるのに、
**本体連動か別式かを決められなかった**（[trial01_quant](../simulation/sim05/analysis/per_trial/trial01_quant.md) §4-2）。
**データ量を増やすと分散は減るが、識別できない量は何点取っても識別できない。**
∴ **ablation（1本ずつ足す）が正解**で、**volume は各設計点の繰り返し（n 稼ぎ）に充てる**
（実機ばらつき CV 約10% を潰す効果は本物）。

**★ablation の優先順位**（コードで枠を確認済＝**効く枠が違うので情報量が違う**）:

#### ★ `puvoir` の扱い（ユーザー指摘 2026-08-06 への回答）

> **ユーザー指摘**: 「puvoir のリキャストにはバーストを複数回行う必要があり、その場合バースト効果で余計なバフが混入する。
> **1 stack までしか純粋な効果量は測れなそう**」。

**① 結論から: 1 stack で足りる。複数 stack を作る必要はない。**

**② ⚠まず Claude Code の記述を訂正**: 前版で `puvoir` を「上限UP のみ」と書いたのは**誤り**。
一次情報（`gamedata/md/神姫/hecate.md` §1 アビ1）＝「味方全体の**光属性攻撃**・**ダメージ上限**UP(累積可)」
＝シムでも **`elem_puvoir=+0.15`/stack（raw）と `cap_puvoir=+0.06`/stack（cap）の2枠**を持つ。**純粋な cap レバーではない。**

**③ それでも分離できる**: cap は**ほぼ等倍**で効き、raw は **slope 0.04 倍**に潰れて効く（trial01_quant §3.5）。
∴ **cap/raw 比が違う成分には、2つの効果が違う配合で載る**＝**2成分以上を読めば連立で解ける**:

| 成分 | Δout（1 puvoir stack・シム予測） | 内 cap 由来 | 内 elem(raw) 由来 | **cap 由来の割合** | 実機hit/押下 |
|---|---|---|---|---|---|
| **holy 8hit** | **+3.11%** | +1.89% | +1.22% | **60.8%** | **8** |
| **judg ph0** | **+2.98%** | +2.07% | +0.91% | **69.4%** | **10** |
| consort | +2.72% | +2.13% | +0.60% | 78.1% | 2 |

**配合比（elem 感度 ÷ cap 感度）が 0.258 / 0.176 / 0.112 と散る**＝**2成分あれば `cap_puvoir` と `elem_puvoir` を別々に推定できる**。

**④ ★バーストは1回も要らない**（＝ユーザーの懸念そのものが回避できる）:
`holy`（アリアン1・黄）・`judg` ph0（テトラ・赤だが ph0 はバーストではない）・`consort`（ナポ3・赤だが
**`burstTrigger` フラグを持たない**＝バーストしない）は、**バーストボタン OFF のまま押せる**。
∴ **「puvoir 無し → puvoir 1 stack」の2条件を、バーストを1度も発生させずに比較できる**。
⚠ **`burstTrigger` を持つのは `effond` と `elegant` だけ**＝この2つと `alone`／`judg` ph1 を踏まなければバーストは起きない。
⚠ `judg` は**押すたびに ph0→ph1→ph2 と巡る**＝**1走で judg は1回だけ**（ph0 のみ）に留める。

**⑤ 精度は足りる**（trial01 の実データから検算）:
holy 1押下8ヒットの**ヒット間 CV は実測 1.04%**（trial01 #10 の8値から算出）。
∴ 1押下の平均の SE は **0.35%**、3押下ずつなら差の SE は **0.29%** ＝ **効果 3.11% は約 10σ**。**十分に見える。**
⚠ ただし**バフ状態を揃えること**が絶対条件（trial01 では holy の押下平均が 517,737 → 614,311 とターン内で 19% 上昇している）。
**puvoir 以外は完全に同一手順**にする。

**⑥ そもそもリキャストにバーストが要るのか**: シム定義では `puvoir` は **CD 2・効果6T**＝
**ボタン OFF で溜めている間にターンが進めば、バースト無しで T1/T3/T5 と 3 stack まで積める**はず。
⚠ **ここは実機の挙動が正**＝もし実機で「バーストしないと CD が戻らない」等の制約があれば、**④⑤ により 1 stack で完結する**ので問題にならない。
